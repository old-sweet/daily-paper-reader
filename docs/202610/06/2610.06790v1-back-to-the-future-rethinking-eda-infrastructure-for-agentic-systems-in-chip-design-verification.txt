## Abstract 

The unprecedented computational scale of modern artificial intelligence depends on complex, multi-billion-transistor Systems-on-Chip—yet the workflows that verify these chips remain stubbornly manual. Although Large Language Models (LLMs) have made rapid inroads into Electronic Design Automation (EDA), approximately 74.6% of existing studies target static Register-Transfer Level (RTL) code gen-eration, leaving post-simulation verification and interactive waveform debugging largely untouched. We introduce Back-to-the-Future (BTTF) , an end-to-end agentic framework that closes this infrastructural gap. BTTF distills massive, unstructured simulation dumps into a normalized relational SQLite database and couples it with a collaborative multi-agent orchestration engine that translates natural-language verification queries into schema-aware SQL while correlating signal anomalies with versioned RTL repositories. Across a 150-query bench-mark, BTTF attains 95.33% execution accuracy, charting a practical path toward autonomous EDA verification. 

## 1 Introduction 

Sustaining the computational demands of modern AI beyond the end of Moore’s law increasingly hinges on highly heterogeneous Systems-on-Chip (SoCs) [1]. As architectural complexity grows, design flows built on Hardware Description Languages (HDLs) become ever more labor-intensive, iterative, and error-prone [2]. Verification alone now consumes over 70% of the development cycle becoming the primary bottleneck of modern chip design [3], and functional bugs that slip into full-chip regression or post-silicon testing carry exponential financial and schedule penalties. Hence, automating register-transfer level (RTL) verification and analysis is an urgent, high-impact goal for the Electronic Design Automation (EDA) community. The rapid advances of Large Language Models (LLMs) has naturally inspired a wave of AI-assisted EDA research [4, 5]. This wave, however, is strikingly lopsided. While approximately 74.6% of LLM-for-hardware studies concentrate on front-end RTL code generation and synthesis [6], post-simulation waveform debugging and dynamic verification remain largely underexplored. Since hardware development demands rigorous testing as much as design synthesis, this neglect leaves a substantial share of the automation opportunity untapped. Even the few LLM-aided verification workflows that do exist operate almost exclusively on static source code or toy-scale simulation logs, whereas interactive post-simulation debugging is a fun-damentally harder problem. When a dynamic simulation fails, engineers manually scrub through terabytes of temporal dumps in graphical waveform viewers, tracing illegal transitions back to their origin in the HDL hierarchy. Raw, ASCII-based waveform dumps exceed model context windows by orders of magnitude, carry no structured semantic index, and expose no native, low-latency query interface that an autonomous agent could invoke. Here, we propose Back-to-the-Future (BTTF) , an end-to-end agentic framework that enables natural-language querying for root-cause analysis and formal verification over complex RTL wave-forms. Rather than forcing waveforms into an LLM’s context, BTTF revisits a classical EDA paradigm. It recasts unstructured temporal waveforms as a normalized relational SQLite database, then pairs this schema with a collaborative multi-agent engine that plans, queries, and audits on the engineer’s behalf. On 150 expert-annotated queries, BTTF reaches 95.33% overall accuracy, and its multi-agent design outscores a monolithic single-agent baseline by 17.3% on a five-criteria quality audit. 

## 2 Related Work 

LLM-Driven Hardware Verification. LLMs have demonstrated remarkable capacity across EDA research, assisting developers with bug localization, code generation, and automated veri-fication [2, 4, 5, 7, 8, 9]. For complex verification tasks, state-of-the-art systems increasingly adopt multi-agent orchestration flows that split hardware synthesis into specialized roles for generation, testbench simulation, and formal counterexample refinement [5, 7, 10]. Yet these frameworks operate predominantly on static source code, compile-time assertion lists, or toy-scale simulation logs, im-plicitly assuming an LLM can localize functional errors from static HDL traces or terse compiler messages alone. 

Key Limitation and Our Observation. The closest attempt to bridge this gap equips a coding agent with an Abstract Syntax Tree (AST)-based waveform tracing tool [11], but such traces remain tied to small, code-centric examples rather than production dumps. BTTF instead builds on a complementary observation: SQL generation is an emergent capability of LLMs, rooted in their deep semantic mapping from natural language to structured code [12]. Once waveforms are made 

relational , decades of database machinery (e.g., indexing, aggregation, low-latency filtering) become directly accessible to language agents. 

## 3 BTTF Framework 

Figure 1: Overview of BTTF framework. As Figure 1 illustrates, BTTF comprises two coupled subsystems on opposite sides of a single relational contract: (1) an offline Waveform Preprocessing Pipeline that compresses bulky simula-tion dumps into an optimized relational SQLite schema, and (2) an online Agentic Orchestration Engine that translates natural-language verification queries into schema-aware SQL and carries out the verification itself. 

3.1 Waveform Preprocessing Pipeline 

Standard EDA simulators emit proprietary binary waveforms ( .fsdb ) or ASCII Value Change Dump (.vcd ) files; for SoC-scale blocks, a raw VCD text file routinely exceeds 10 GB—far beyond any prospect of direct context embedding. The BTTF pipeline therefore extracts the target hierarchies and normalizes them into a relational SQLite database ( waves.db ) built around two primary tables: 2• signal_metadata captures the static signal declarations (RTL signal name and its variable type, etc.) with id. • signal_changes records the temporal behavior as timestamped transitions as a (time, value) 

with a foreign key to refer metadata. Separating who a signal is from what it does lets agents reason over structure and time independently, joining the two only when a query demands it. A naïve translation of every value change would simply move the scalability problem from the filesystem into the database. BTTF instead applies coverage-aware pruning during on-the-fly database generation: • Clock pruning . High-frequency clock toggles dominate table size while carrying little debug information; since every row in signal_changes is timestamped, clock transitions can be skipped at insertion time without losing temporal anchoring. • On-the-fly inactive-signal pruning (ZERO /AVG ). To cope with duplicate VCD identifiers and inactive nets, the ingestion engine maintains a lightweight hash map ( vcd_id_to_db_id ) alongside a per-signal transition counter ( signal_change_count ). This bookkeeping enables two graduated policies: dropping statically silent zero-toggle wires ( ZERO ), or additionally dropping nets whose toggle rate falls below the design-wide average ( AVG ). • Batched insertion. Row-by-row insertion incurs severe SQLite transaction overhead. Grouping transitions into batched writes removes this bottleneck at ingestion time. 

3.2 LLM-Driven Agent Orchestration 

On top of the generated waves.db , BTTF conducts verification through a collaborative multi-agent architecture. The main Orchestration Agent decomposes a natural-language query into sub-goals, routes them to specialized agents with own toolsets, and audits the merged answer. • Analysis Agent. Armed with schema-aware multi-query execution tools, it composes SQLite queries over the two tables to handle scope discovery, event inspection, and toggle counting. For complex tasks such as power hotspot detection, it leverages an iterative function-calling loop to execute multi-turn queries and aggregate multi-cycle signal statistics. • Verification Agent. Tying waveform anomalies back to version-controlled source by evaluat-ing SVA rules ( ASSERT , ASSERT_STATIC , ASSERT_NEVER , ASSERT_KNOWN , COVER ) through the regular expression (REGEX) assignment. • Evaluation Agent. Before any root-cause analysis is returned, this agent audits candidate queries against five criteria: (1) correctness —filtering, aggregation, and join fidelity to user intent; (2) 

completeness —inclusion of all required columns and time conditions; (3) efficiency —proper indexing and avoidance of redundant joins; (4) schema adherence —strict conformance to the two-table schema; and (5) context understanding —correct inference of implicit simulation timescales and hierarchy scopes. Under the orchestrator, agents communicate solely through a dynamic session context maintained across turns; together with a self-correction loop on failed queries, this shared-memory discipline lets each agent stay narrowly specialized without losing global coherence. Furthermore, when an assertion rule is violated even after self-correction, the agent autonomously isolates the exact violation timestamp and pinpoints the problematic sub-signals responsible for the failure (see Appendix A.1 for detailed root-cause diagnostics). 

## 4 Results 

Experimental setup. All agents are served through the Gemini API with Gemini-2.5-Pro as the default model. Our benchmark spans multiple SoC design hierarchies of varying complexity (4.2 GB of VCD, 18,450 nets), from which we extract simulation windows ranging from narrow 50 ns high-resolution glitch-debug windows to 800 ns full-transaction simulation dumps. We curate 150 natural-language verification queries representative of daily engineering workflows, each paired with an expert-annotated golden answer.

## 5 Discussion and Conclusion 

Our BTTF argues, and empirically supports, a simple thesis. The binding constraint on agentic wave-form debugging is data infrastructure, not model capability. By recasting terabyte-scale waveforms into a compact, vendor-agnostic relational schema, BTTF turns an intractable context problem into a routine text-to-SQL problem—one at which modern LLMs already excel—and its orchestration engine converts that access into grounded, audited root-cause analysis. The 95.33% benchmark accuracy and 17.3% quality gain from agent specialization suggest that autonomous EDA verification will be reached through better interfaces between agents and design data rather than ever-larger models alone. To scale across larger full-chip designs, streaming ingestion, standardized scope-path normalization, and a waveform-to-RTL symbol index are the natural next steps; evaluating larger frontier reasoning models to tackle multi-hop causal tracing over these stores remains an exciting direction for future work. More broadly, the recipe behind BTTF—normalize an opaque EDA 4artifact into a queryable store, then let specialized agents operate over it—extends naturally beyond waveforms to regression logs, coverage databases, and power traces. We therefore view BTTF less as a point tool than as a template for rebuilding EDA infrastructure to meet agents halfway, and we hope it encourages the community to treat data interfaces as a first-class research object in AI-driven chip design.

## A Appendix: Detailed Query Execution Workflow and Output Analysis 

A.1 Handling Assertion Failures and Root-Cause Diagnostics 

In standard simulation logs, assertion checkers typically emit binary pass/fail flags without pin-pointing the originating nets. Within BTTF, when an assertion rule (such as ASSERT_NEVER or 

ASSERT_KNOWN ) fails during dynamic checking, the agent automatically extracts the exact violation timestamp tviolation where the condition evaluates to true or where an invalid X/Z state is detected. It then initiates backward causal tracing by querying the prior values of all antecedent operands in the assertion expression at t ≤ tviolation . Consequently, the final diagnostic response explicitly highlights the specific sub-signal responsible for the failure (e.g., “Assertion failed at t = 6929 ns due to net 

req_sel transitioning to unknown state x while clk was high”), bridging the gap between high-level assertion monitoring and low-level root-cause debugging. 6A.2 End-to-End Query-to-Response Pipeline

The agent leverages schema context to map the natural language scope into a structured function invocation ( find_signal_in_scope ) or a relational SQL join across signal_metadata and changes .
