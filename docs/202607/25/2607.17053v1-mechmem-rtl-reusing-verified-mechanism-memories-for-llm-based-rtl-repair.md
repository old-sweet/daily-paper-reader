## 摘要
大型语言模型（LLM）能够自动修复寄存器传输级（RTL）设计。然而，修复复杂的时序逻辑错误需要复用过去的调试经验。现有的检索增强生成（RAG）依赖任务文本相似性来提供这些经验。这种基于文本的方法常常误导模型，因为自然语言难以准确反映周期级硬件执行语义。为此，我们提出MechMem-RTL，一个复用验证器确认的修复记录而非文本相似性的修复框架。每条存储记录严格关联触发证据、诊断出的故障机制、局部修复动作、保持约束和验证摘要。对于新故障，MechMem-RTL仅在确定性验证器证据与存储的触发条件严格兼容时注入历史记录。否则，系统仅使用当前验证器证据。我们在48个公共时序RTL任务上对六种修复模型评估了MechMem-RTL。每个任务最多尝试两次修复，MechMem-RTL成功解决了288个任务-模型对中的180个，优于标准反馈修复（109对）和任务相似性RAG（107对）。

## Abstract
Large language models (LLMs) can automatically repair register-transfer-level (RTL) designs. However, fixing complex sequential logic errors requires reusing past debugging experience. Existing retrieval-augmented generation (RAG) relies on task-text similarity to provide this experience. This text-based approach often misguides the model because natural language poorly reflects cycle-level hardware execution semantics. To address this, we present MechMem-RTL, a repair framework that reuses verifier-confirmed repair records instead of text similarity. Each stored record strictly links trigger evidence, a diagnosed failure mechanism, a local repair action, preservation constraints, and a verification summary. For a new failure, MechMem-RTL injects a past record only when deterministic verifier evidence is strictly compatible with the stored trigger. Otherwise, the system uses only current verifier evidence. We evaluate MechMem-RTL on 48 public sequential RTL tasks across six repair models. With at most two repair attempts per task, MechMem-RTL successfully resolves 180 out of 288 task-model pairs, outperforming standard feedback repair (109 pairs) and task-similarity RAG (107 pairs).

## 1. 核心问题与整体含义（研究动机和背景）
- **核心问题**：大型语言模型（LLM）在自动修复 RTL（寄存器传输级）设计时，修复复杂时序逻辑错误（如有限状态机转移、协议边界等）尤为困难，因为验证器只报告表面症状（如特定时钟周期的信号不匹配），而不指出结构根因。LLM 缺乏直接建模硬件周期级语义的能力，需要复用过去的调试经验来弥补这一差距。
- **现有方法局限**：基于文本相似性的检索增强生成（RAG）是常见经验复用方式，但文本相似性对时序硬件行为是弱代理——任务描述完全不同但可能因同一种状态更新错误失败，而相似描述可能因完全不同的周期级原因失败。因此，文本相似性常常误导模型。
- **整体含义**：提出一种基于确定性验证器证据（而非文本相似性）的经验复用机制，通过严格匹配故障触发条件来注入历史已验证的修复记录，从而显著提升复杂时序错误的修复成功率。

## 2. 方法论
- **核心思想**：构建并复用“验证器确认的机制记忆”（Verifier-confirmed Mechanism Memory）。每条记忆记录是一个五元组 (T, M, R, P, V)，分别表示：触发证据（验证阶段、失败种类、受影响输出、首次不匹配时间等）、诊断出的故障机制、局部修复动作、行为保持约束、验证摘要（失败→通过的状态转变）。记忆仅在补丁通过可执行测试台后才被存储，确保其锚定于可验证的硬件证据。
- **关键技术细节**：
  - **确定性证据过滤器**：对新故障，系统首先根据宽带归一化验证器证据检索候选记录，然后通过确定性规则筛选——严格比较验证阶段、失败种类、影响输出信号、时间诊断特征等，并排除来自同一任务或重复任务的记录。只有当证据严格兼容时，才将存储的记忆注入提示（prompt）中；否则，仅使用当前验证器证据构建修复上下文。
  - **提示构建**：提示包含当前故障 RTL、即时验证器反馈，以及（如果过滤器通过）兼容的记忆记录。明确要求模型诊断故障机制并返回局部补丁，指定修改区域和需保持的行为。
  - **后处理**：强制补丁保持原始模块接口，限制修改范围，并跟踪响应有效性、约束违反、行修改数等诊断指标。
- **算法流程**（文字说明）：
  1. 输入：任务规格、当前故障 RTL、最新验证器报告。
  2. 对验证器证据进行归一化解析（阶段、种类、信号、时序）。
  3. 从记忆库中检索候选记录，应用确定性证据过滤器。
  4. 若存在兼容记录，将记忆注入提示；否则使用当前证据。
  5. LLM 生成局部补丁，重新编译和仿真。
  6. 若通过测试台，存储新的五元组记忆；若失败，更新验证器反馈，重复步骤2-5，最多两次尝试。
