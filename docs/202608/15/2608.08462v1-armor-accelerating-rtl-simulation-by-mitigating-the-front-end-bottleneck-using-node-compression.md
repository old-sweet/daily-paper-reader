## 摘要
RTL仿真在芯片设计中不可或缺。高性能仿真器通常将RTL图中的每个节点降低为一条指令序列。尽管这种逐节点降低能够实现激进的编译器优化，但它显著增加了代码占用空间，严重超出指令缓存容量并导致前端瓶颈。我们的性能分析显示，超过50%的流水线停顿由CPU前端引起，成为当前最先进RTL仿真器的关键性能瓶颈。然而，在充分利用完全展开RTL图的优化收益的同时，减少代码占用空间以缓解前端瓶颈仍然极具挑战。在本文中，我们提出ARMOR，一种高效的RTL仿真器，旨在通过节点压缩缓解前端瓶颈。关键思路是利用展开RTL图所暴露的数据并行性，以及逐节点降低所揭示的位空间利用率不足，借助位级数据并行同时压缩多个节点，使得单条指令序列能够服务多个节点而非每个节点一条。为了实现有收益的节点压缩，我们首先提出一种模块感知的同构子图识别方法，利用跨模块实例的结构同构性，在子图层面系统地识别压缩机会。然后，我们提出一种对齐感知的密集打包策略，根据数据流依赖将节点分组为包，同时保留数据重用，并辅以贪心合并策略以提升位空间利用率。最后，我们实现统一的位级并行方案，以支持压缩节点的位级并行执行。实验结果表明，与最先进的仿真器相比，ARMOR在CPU设计上实现了1.6倍加速，在AI加速器上实现了2.7倍加速。

## Abstract
RTL simulation is indispensable in chip design. High-performance simulators typically lower each node in the RTL graph into an instruction sequence. Although this per-node lowering enables aggressive compiler optimizations, it dramatically increases the code footprint, severely exceeding instruction cache capacity and causing front-end bottlenecks. Our profiling reveals that over 50% of pipeline stalls are caused by the CPU front-end, becoming a key performance bottleneck in state-of-the-art RTL simulators. However, reaping the optimization benefits of fully unrolling the RTL graph while simultaneously reducing the code footprint to mitigate front-end bottlenecks remains highly challenging. In this paper, we propose ARMOR, an efficient RTL simulator designed to alleviate the front-end bottleneck through node compression. The key idea is to exploit the data parallelism exposed by the unrolling RTL graph and the insufficient bit-space utilization revealed by per-node lowering, leveraging bit-level data parallelism to compress multiple nodes simultaneously, so that a single instruction sequence can serve multiple nodes instead of one per node. To achieve profitable node compression, we first propose a module-aware isomorphic subgraph identification method that leverages structural isomorphism across module instances to systematically identify compression opportunities at the subgraph level. We then propose an alignment-aware dense packing strategy that groups nodes into packs according to dataflow dependencies while preserving data reuse, complemented by greedy merging strategies to enhance bit-space utilization. Finally, we implement a unified bit-level parallelism scheme to support bit-level parallel execution of compressed nodes. Experimental results show that ARMOR achieves 1.6x speedup on CPU designs and 2.7x speedup on AI accelerators compared to state-of-the-art simulators.

- RTL（寄存器传输级）仿真是芯片设计与验证中的基础环节。高性能编译型仿真器（如 Verilator）通常将 RTL 图中的每个节点（加法器、寄存器、逻辑门等）分别降低为一段指令序列。
- 这种“逐节点降低”虽然使代码完全展开、便于编译器做静态优化，但会导致：
  - 生成的指令工作集急剧膨胀，远超 L1 指令缓存（通常仅 32KB）容量；
  - CPU 前端（取指、解码、指令分发）成为严重瓶颈。
- 论文实测发现：Verilator 在 Conv2D 和 Boom 设计上，超过 70% 的流水线空闲由前端不足造成；动态工作集可达数百至数千 KB，比 L1I 缓存高一个数量级以上。
- 已有缓解方案存在明显弊端：
  - 循环化表示（如 RTeAAL Sim）或代码重用（如 Dedup）虽缩小代码体积，但牺牲了完全展开带来的静态特化能力，导致运行时内存访问增多，反而加剧后端瓶颈。
  - 硬件级前端优化（指令预取、缓存替换策略）成本高、灵活性差，难以惠及已有 CPU。
- 因此，论文的核心问题是：**在保持 RTL 图完全展开（保留静态特化收益）的前提下，如何缩小代码占用空间，从而缓解前端瓶颈。**

## 2. 论文提出的方法论

### 核心思想
- **节点压缩（Node Compression）**：利用 RTL 图展开后暴露的数据并行性，以及低比特宽节点（>80% 节点位宽小于 16 位）对 64 位机器字的空间浪费，将多个同构节点映射到同一机器字的不同位片（bit-slice），由**一条共享指令序列**同时计算多个节点。
- 这样做既能保留全展开代码的静态优化优势，又能显著减少指令工作集，同时降低实际执行的操作数。

### 关键技术细节

**阶段一：模块感知的同构子图识别与对齐（Module-Aware Isomorphic Subgraph Identification & Alignment）**

- 动机：RTL 图规模大，通用子图同构搜索是 NP-hard 问题，不可行。
- 观察：RTL 图由模块实例化构成，高并行架构中同一模块被大量复用（平均复用率约 85%），同一模块的多个实例天然构成同构子图。
- 做法：
  1. 构建平面数据流图 $G_f=(V,E_f)$ 与层次图 $G_h=(M,E_h)$，建立节点到模块实例的映射 $\phi: V \to M$；
  2. 按模块类型分组实例；
  3. 对每个模块类型，提取每个实例对应的节点集合；
  4. 利用“模块内节点名称唯一”的特性，将不同实例中同名节点对齐，形成**压缩域（Compression Domain）** $D$。
- 效果：将子图同构匹配问题降为线性时间分组，避开组合爆炸。

**阶段二：对齐感知的密集节点打包（Alignment-Aware Dense Node Packing）**

- 目标：将压缩域中的节点组织为满足硬件位宽约束、无数据依赖、且保持生产者–消费者对齐关系的“包（pack）”。
- 需要权衡：位空间利用率最大化 vs 数据布局可复用（避免频繁数据重排）。
- 算法要点（对应 Algorithm 2）：
  1. 按拓扑层级划分压缩域，保证同一包内节点无依赖；
  2. 构建子压缩域之间的依赖图 $G$；
  3. 拓扑遍历 $G$，从最大可行组（Maximal Feasible Group，取最多不超过 $\lfloor W/w\rfloor$ 个同域节点）出发作为种子包；
  4. 沿数据依赖进行对齐感知扩展：新包中的节点必须来自同一压缩域，且与种子包保持生产者–消费者对应关系；
  5. 扩展完成后再做域内贪心合并（Intra-Domain Merging），进一步提升位空间利用率。
- 整体策略可概括为“**对齐优先、密度次之**”，在数据重排开销与位利用率之间取得平衡。

**阶段三：位级压缩执行（Bit-Level Compression Execution）**

- 按跨切片依赖关系将 RTL 操作分为两类，并分别处理：

| 操作类型 | 示例 | 压缩执行策略 |
| --- | --- | --- |
| 切片独立（slice-independent） | AND、OR、NOT 等逻辑运算；寄存器读写等内存访问 | 直接进行位级并行计算；内存访问采用“包对齐”的存储布局，一个包独占一个机器字，避免逐切片访问和重排 |
| 跨切片依赖（cross-slice dependent） | 相等比较（Eq）、移位、位提取 | 使用 BMI2 的 PDEP/PEXT 实现位沉积/抽取；Eq 在 AI 加速器场景（低比特宽）用“XOR + PEXT + OR”实现；在 CPU 场景（宽操作数）识别“共享非常量操作数 + 常量操作数”的 Eq 组，用 LUT 查找表压缩为单次表更新 |

- 代码生成时，将与位布局相关的操作显式转换为 `_pext_u64`/`_pdep_u64` 内建函数，由 C++ 编译器在支持 BMI2 的目标平台生成对应指令。

- 扩展性：随架构并行度（PE 数或核数）提升，ARMOR 的压缩收益单调增加；在 Boom-8C 上达到最高 1.95× 加速比，证实了“模块复用率越高、同构子图越多，压缩优势越明显”的核心假设。

## 7. 局限性、潜在问题与未来方向

- **输入依赖**：ARMOR 高度依赖 FIRRTL 中的模块实例化结构和“实例内同名节点”的对齐假设。若输入为扁平化、无层次信息的网表，或模块实例被优化器打散，则模块感知识别会失效，退化为低效的通用同构搜索。
- **位宽约束**：压缩域中每个包最多容纳 $\lfloor W/w \rfloor$ 个节点，其中 $W$ 为机器字长（64 位），$w$ 为节点位宽。对于位宽较大（如 32 位以上）的节点，压缩收益急剧下降；论文实验数据宽度也仅覆盖 2–16 位，未验证 32 位量产设计中的效果。
- **动态布局重排开销**：虽然对齐优先策略减少了数据重排，但仍有约 22.7% 的指令开销源于位布局转换。在依赖链较长、跨压缩域频繁切换的场景，这部分成本可能抵消压缩收益。
- **内存访问模型**：论文将寄存器/内存访问也视为可压缩节点，但真实 RTL 中存储器端口冲突、行列访问模式等复杂行为未被完全建模，可能对仿真精度或性能产生潜在影响。
- **适用范围**：ARMOR 主要面向数据并行、模块高度复用的设计（AI 加速器、多核 CPU），对控制流密集、模块实例少的设计（如随机逻辑控制器）价值有限。
- **未报告编译开销**：论文未给出 ARMOR 的编译时间、峰值内存占用等成本。考虑到压缩域构建和依赖图遍历需处理百万级节点，编译端开销可能显著高于 Verilator，但作者未予以量化。
- **硬件要求**：依赖 BMI2 指令（PDEP/PEXT），老旧 x86 平台或非 x86 架构（如 ARM/RISC-V）无法直接生成对应指令，需软件模拟，性能会大打折扣。

## 8. 总体评估与参考价值

- **优点**：
  - 问题定位精准，通过微架构分析确证了前端瓶颈是编译仿真器的主要矛盾；
  - 方法具有较好的理论清晰度——将“压缩”分为子图识别、打包、执行三个层次，且每层都有针对性的算法或指令映射；
  - 实验体系完整，涵盖性能、微架构、消融、扩展性、平台差异等多个维度，结论具有说服力；
  - 从“代码复用”和“数据位宽”两个角度同时出发，与以往纯软件缓存优化或纯硬件预取方法形成互补。
- **缺点与争议**：
  - 依赖 FIRRTL 层次结构，通用性存疑；对非 Chisel/FIRRTL 生态的商用 RTL 流程，需要额外预处理；
  - 未与最新商业仿真器（如 Synopsys VCS、Cadence Xcelium）直接对比，其加速比可能无法直接推广到工业环境；
  - 压缩率的报告方式（静态节点数、隐式指令数等）与真实 IPC 之间的因果链条尚可进一步量化，以证明“压缩节点数”到“前端 bound 下降”的必然性。
- **未来方向**：
  - 将压缩扩展到扁平网表，使用图嵌入或哈希指纹近似识别同构子图；
  - 结合动态二进制翻译或 JIT，在运行时根据热点动态调整压缩域；
  - 支持异构机器字长（SIMD 向量寄存器位宽），进一步提高位空间利用率；
  - 探索将压缩与多线程并行仿真结合，减少跨线程的布局同步开销。

**总结**：ARMOR 提出了一种富有启发性的“位级代码压缩”方案，利用 RTL 中天然的海量低比特宽节点和模块复用结构，将多节点合并到同一机器字内执行，在保持全展开静态优化优势的同时显著缩小指令工作集，缓解了 CPU 前端瓶颈。论文实验设计严谨，结果清晰，虽有一定适用范围限制，但为编译型仿真的性能优化提供了新的、可借鉴的研究方向。
