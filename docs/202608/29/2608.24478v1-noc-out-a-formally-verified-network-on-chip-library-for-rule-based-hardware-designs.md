## 摘要
片上网络（NoC）是多处理器芯片的通信骨干。NoC的故障会对整个系统造成严重后果。然而，目前尚无方法能够在无需繁琐验证工作的情况下提供具有强保证的形式化验证NoC。任何生成形式化验证NoC的库都需要在NoC结构上是参数化的。这要求硬件描述语言（HDL）支持参数化、并发且高效的硬件设计，并具备必要的程序逻辑以模块化方式对其进行推理。迄今为止，HDL在这两方面都存在不足。在本文中，我们实现了NoC-Out，这是首个用于形式化验证的k维NoC设计的库/生成器。为了构建NoC-Out，我们扩展了Rocq定理证明器中的基于规则的HDL Kôika，使其支持并发且高效的NoC设计，并提供了用于模块化、自动化推理的程序逻辑。给定配置后，NoC-Out在Kôika中生成k维环面NoC，并可编译为Verilog。每个生成的NoC都附带一个证明，证明其精化符合我们的形式化NoC规范；无需额外验证工作。我们的规范证明了强活性保证，因此适用于所有生成的NoC。在评估中，我们发现我们的验证方法甚至是合成基于规则的HDL中高效NoC所必需的。

## Abstract
The Network-on-Chip (NoC) is the communication backbone of any multiprocessor chip. A failure of the NoC has severe consequences for the whole system. Yet, no approach exists that provides formally-verified NoCs with strong guarantees but without tedious verification effort.   Any library that generates formally-verified NoCs needs to be parametric in the structure of the NoC. This requires a hardware description language (HDL) that allows for parametric and concurrent yet efficient hardware designs as well as the necessary program logic to reason about them in a modular fashion. So far, HDLs fall short in both aspects.   In this paper, we implement NoC-Out, the first library/generator for formally-verified k-dimensional NoC designs. In order to build NoC-Out, we extended Kôika, a rule-based HDL in the Rocq theorem prover, with support for concurrent yet efficient NoC designs and a program logic for modular, automated reasoning. Given a configuration, NoC-Out produces a k-dimensional torus NoC in Kôika, which can then be compiled to Verilog. Each produced NoC is equipped with a proof that it refines our formal NoC specification; no additional verification effort is required. Our specification proves a strong liveness guarantee, which consequently applies to all generated NoCs. In our evaluation, we find that our verification approach is even required to synthesize efficient NoCs in rule-based HDLs.

## 2. 论文提出的方法论：核心思想、关键技术细节

### 2.1 整体架构（图 1）
- 基于 Rocq 定理证明器中的规则式 HDL **Kôika** 构建 NoC-Out。
- NoC-Out 接收 NoC 配置（维度列表 `dims` 和数据类型 `data_t`），生成 Kôika 程序，再编译为 Verilog。

### 2.2 Kôika 扩展之一：Read-After-Write (RAW) 语义
- **原有问题**：Kôika 的事务性语义中，如果前一个 action 写入了寄存器，后一个 action 若再 `read 0(r)` 会直接 abort，导致并发受限制，迫使设计者使用额外的中间寄存器，降低硬件效率并增加推理复杂度。
- **RAW 语义**：在原有语义中添加 `raw` 开关，允许读取之前写入的值，即省略 `read 0/read 1` 的前置条件（如图 9 中的 `Read0_raw` 和 `Read1_raw`）。  
  - 该语义只影响读取规则，其余语言构造不变。  
  - 编译器及编译器正确性定理相应更新，数据竞争自由保证仍成立。
- **效果**：  
  - 缓解了并发 NoC 设计中不必要的 abort；  
  - 将单个寄存器的可区分状态从 7 种（原始语义）简化为 3 种（RAW 语义），显著降低推理复杂度（见图 10）。

### 2.3 Kôika 扩展之二：程序逻辑（Hoare Logic）
- 定义断言为 `P(R, L, Γ)`，其中 `R` 是寄存器环境，`L` 是合并后的访问日志，`Γ` 是变量上下文。
- 定义弱前置条件（WP）和 Hoare 三元组（部分和总体），支持模块化推理与符号执行自动化。
- 关键推理规则（如 `HRead0`、`HRead1`、`HWrite`、`Abort`）用于处理寄存器的读/写和异常情况。
- 通过寄存器状态关系（见图 11）简化对寄存器值变化的断言描述。
- 证明了程序逻辑的 soundness（Adequacy of actions / schedules）。

### 2.4 参数化 NoC 库设计
- **拓扑**：k 维 torus，每个节点通过双向通道连接邻居，具有维度内回绕链路。
- **路由**：采用维度顺序路由（dimension-order routing），对每个维度选择最短方向（向上或向下），并通过虚拟通道（high/low）避免死锁。
- **仲裁**：采用轮询（round-robin）仲裁器，优先指针 `p` 选择最近的有效请求，并在每次转发后更新。
- **实现**：利用 Rocq 元编程在 Kôika 中生成依赖类型的寄存器集和路由/仲裁逻辑，实现高度参数化设计。

### 2.5 精化证明与活性保证
- 分别证明 **路由精化引理**、**仲裁精化引理** 和 **NoC 精化定理**：  
  `[is_repr s] noc_schedule dims [is_repr (ns_step 1 s)]`  
  即每个硬件周期都符合规范 `ns_step` 的抽象语义。
- 在规范层面证明 **无死锁定理**（Deadlock freedom）和 **NoC 活性定理**（NoC liveness）：任意消息最终到达目的地。
- 由于精化证明和活性证明均面向所有 k 维配置，因此所有生成的 NoC 自动继承这些保证。

## 7. 优点

- **开创性**：首次将 NoC 的形式化验证从“每个实例分别证明”提升到“一次高阶证明覆盖所有实例”。
- **模块化与自动化**：基于 Hoare 逻辑的程序逻辑支持符号执行和自动化证明，显著降低证书工作量。
- **并发效率提升**：RAW 语义解决了规则式 HDL 中不必要的读后写冲突，支持更自然的并发硬件设计。
- **强规范与活性的结合**：在规范层面证明死锁自由与消息最终送达，且通过与精化证明的组合传递到硬件实现。
- **可扩展性**：参数化支持任意维度数和维度大小，远超 SystemVerilog 等传统 HDL 的表达能力。

## 8. 不足与局限

- **通道模型简化**：目前通道仅支持容量为 1 的队列，未扩展到更深的 FIFO，限制了实际 NoC 的性能探索。
- **编译器正确性缺口**：为移除事务检查电路而添加的编译器 flag 绕过了原有编译器正确性定理；需要重新设计编译器并证明性质保持（WP-preserving compilation）才能恢复端到端保证，论文将其留作未来工作。
- **实验覆盖有限**：仅评估了关键路径延迟，未涉及面积、功耗、吞吐量等关键指标，也缺乏与主流 NoC 设计或验证流程的横向对比。
- **硬件映射的局限**：多维 torus 在平面 2D 硅片上的映射本身可能带来额外延迟，论文未对此进行建模或评估。
- **验证噪声**：虽然证明了活性，但证明过程依赖“输出端口必然空闲”的公理（Axiom 5），这要求连接的核必须立即处理到达消息，在真实系统中可能不完全成立。
- **适用范围**：该库面向规则式 HDL（Kôika），对于其他硬件设计语言或非规则式设计流程的可迁移性有限。
