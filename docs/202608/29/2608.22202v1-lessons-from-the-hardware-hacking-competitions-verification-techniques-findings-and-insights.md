## 摘要
硬件破解竞赛已成为评估复杂片上系统（SoC）设计中安全弱点的实用平台，同时促进了安全感知验证和工具开发。本文通过对开放式硬件破解竞赛的系统性研究，探讨了SoC安全验证，重点关注实用的漏洞分析策略、观察到的发现以及安全感知验证的经验教训。我们提出了一种多策略漏洞分析方法，结合了基于仿真的验证、形式化验证、lint分析、大语言模型（LLM）辅助的缺陷检测以及覆盖引导的混合模糊测试。通过分析具有代表性的漏洞发现，阐述了不同技术如何揭示互补类别的安全缺陷，并得出了面向硅前安全验证的实用经验。最后，我们讨论了竞赛基准如何支持新兴硬件安全技术的可复现评估，并指导未来安全感知的EDA研究。

## Abstract
Hardware hacking competitions have emerged as practical platforms for evaluating security weaknesses in complex System-on-Chip (SoC) designs while promoting security-aware verification and tool development. This paper presents a systematic study of SoC security verification through open-box hardware hacking competitions, focusing on practical vulnerability analysis strategies, observed findings, and lessons for security-aware verification. We present a multi-strategy vulnerability analysis methodology, combining simulation-based verification, formal verification, lint analysis, Large Language Model (LLM)-assisted bug detection, and coverage-guided hybrid fuzzing. Representative vulnerability findings are analyzed to illustrate how different techniques expose complementary classes of security flaws, and we derive practical lessons for pre-silicon security verification. Finally, we discuss how competition benchmarks can support the reproducible evaluation of emerging hardware security techniques and guide future security-aware EDA research.

## 1. 核心问题与整体含义（研究动机与背景）

硬件安全是系统安全的基石，但传统设计流程默认假设硬件行为正确且不可篡改。然而，Meltdown、Spectre 以及功耗/故障注入攻击等微架构级漏洞彻底打破了这一假设：硬件实现层面的缺陷，即使仅在 RTL 或门级网表层面，也无法在流片后进行低成本修补，往往需要复杂的工作绕行或重新设计。因此，半导体行业积极推进"shift-left"策略，即在 RTL 设计阶段尽早发现并修复安全弱点。然而，传统电子设计自动化（EDA）流程主要面向功能验证而非安全验证，难以发现设计中非预期的恶意行为。

硬件破解竞赛（如 Hack@DAC、Hack@CHES、Hack@DATE）提供了一个受控、对抗性、现实性的评估环境。与传统的封闭式（closed-box）硬件破解不同，此类"开放式（open-box）"竞赛向参赛者完整提供目标 SoC 的 RTL 设计、规格说明、威胁模型与验证环境，要求参赛者通过多种手段发现漏洞、定位根因并评估安全影响。本论文的核心问题在于：**如何系统化地利用硬件破解竞赛进行 SoC 安全验证，从实证中提炼可复用的漏洞分析方法论、技术经验与工具发展指引**。

## 2. 方法论：核心思想、关键技术细节

论文提出了**多策略漏洞分析方法论**，强调不同技术从不同视角切入设计、交叉验证、互补覆盖。整体工作流分四个阶段：

1. **环境构建与基线执行**：编译设计、运行已有测试（仿真、形式验证、lint 流程）以建立基线；
2. **漏洞候选生成**：各类分析策略并行产出候选漏洞；
3. **候选筛选与去重**：剔除工具错误、无效假设与重复发现；
4. **确认与文档化**：通过自定义测试或形式化反例复现，映射到相应硬件 CWE 类别并记录安全影响与缓解建议。

### 2.1 仿真验证（Simulation-based Verification）

- 采用 Synopsys VCS 与 OpenTitan 自带 DVSim 验证框架结合，搭建基于 HJSON 的自动化编排层。
- 对 SoC 各 IP 执行冒烟测试和回归测试，重点识别失败用例、断言失败、超时和异常状态转换。
- 通过日志与波形分析判断失败是否违反安全需求——只有违反安全要求的失败才被认定为安全相关漏洞。

### 2.2 形式验证（FPV 与 FSV）

- **FPV**：将安全需求转化为 SystemVerilog 断言（SVA），对全部可及行为空间进行穷尽性检查，利用反例定位 RTL 缺陷；主要暴露了密钥清除逻辑错误、寄存器访问控制缺陷、奇偶校验错误处理等问题。
- **FSV**：利用形式化手段检测安全敏感数据源向未授权目的地的信息流，发现了 AES 密钥份额通过软件可见寄存器路径泄漏的机密性破坏问题。

### 2.3 RTL Lint 结构性分析

- 使用 Synopsys VC SpyGlass Lint 全量扫描设计 IP，重点检查不完整赋值、锁存器推断、宽度不匹配、未初始化寄存器、多驱动信号、复位值错误、不可达条件等结构问题。
- 所有 lint 告警均需结合上下文（模块安全功能、关键寄存器、访问控制信号等）进行安全性判断，避免把一般性代码风格警告误报为漏洞。

### 2.4 LLM 辅助漏洞分析

- 流程包括：**安全感知设计分解**（聚焦含密钥、特权信号、生命周期状态、调试授权等安全资产的模块）→ **CWE 识别**（基于设计上下文缩小候选弱点类别）→ **CWE 引导的代码分析**（定向检查访问控制缺失、错误信号依赖、敏感数据传播、FSM 非法转换等）→ **目标安全属性生成**（生成 SVA 假设并交给仿真/形式工具验证）。
- 所有 LLM 生成的断言须经语法和语义双重校验，防止 LLM 幻觉导致的错误属性。

### 2.5 覆盖引导混合模糊测试

- 先运行硬件模糊测试框架收集覆盖率数据，识别未被探索的设计区域；随后将未覆盖点提供给 LLM 生成定向 SVA、测试场景或输入约束；经过验证的产物再回流至模糊测试循环以指导输入生成，从而更高效地探索难以到达的设计状态。

### 2.6 定制 Exploit 开发

- 以漏洞描述为起点，利用 LLM 定位相关 RTL 与验证文件，自动生成 UVM 序列、SVA 监视器或功能检查逻辑，在 OpenTitan 原生验证环境中复现漏洞。论文给出了 UART 和 HMAC 两个详细案例。

## 6. 主要结论与发现

1. **安全意图是识别漏洞的前提**：功能失败≠安全漏洞，分析必须首先明确受保护资产、信任边界、特权规则和预期安全行为，才能正确解读失败测试。
2. **多方法互补是必需而非可选**：仿真擅长复现可执行攻击序列，形式验证适合时序属性与深部状态，静态分析覆盖面广，信息流分析直接检查机密性/完整性。应构建混合验证流，让一种方法的发现自动指导另一种方法。
3. **现有验证设施需要安全感知增强**：传统回归测试以功能覆盖为目标，不能有效覆盖未授权访问、恶意转换和异常错误条件，需要安全导向的刺激生成和覆盖率指标。
4. **自动化发现必须独立验证**：lint 告警、LLM 假设、断言失败、模糊异常都应视为候选漏洞，必须追溯 RTL 根因并通过仿真/形式反例复现确认。
5. **跨层分析不可或缺**：许多漏洞需要结合寄存器事务、固件操作、特权状态等多个抽象层次才能触发，孤立模块分析是不够的。
6. **工具自动化与并行化是竞争力来源**：在竞赛时限内覆盖大型 SoC，需要自动化执行、日志收集、属性检查和结果分诊。

## 7. 优点

- **真实性与实践性**：基于真实竞赛、真实 SoC（OpenTitan）和真实商业工具链，发现的是实际可利用的漏洞，而非合成测试用例——研究结论的可迁移性强。
- **多策略系统化整合**：将传统 EDA 验证手段（仿真、形式、lint）与新兴 AI 技术（LLM 辅助分析）有机融入统一流程，且强调策略间交叉引导而非孤立使用，符合工业界对务实流程的期待。
- **LLM 应用设计严谨**：承认 LLM 输出可能不正确并有针对性设计验证环节（语法+语义双重校验、EDA 工具作为验收标准），避免盲信 LLM。
- **攻击与防御双向视角**：既分析漏洞发现方法，也演示了从漏洞描述到可执行 exploit 的完整闭环（UART 和 HMAC 案例），覆盖了安全分析的核心环节。
- **社区贡献意识**：明确讨论了竞赛基准的可复用性及其在安全感知 EDA 工具评估中的价值，对后续研究具有指导意义。
