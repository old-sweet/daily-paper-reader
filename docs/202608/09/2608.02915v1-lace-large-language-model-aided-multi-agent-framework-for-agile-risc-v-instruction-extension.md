## 摘要
领域特定的指令集架构扩展（ISAX）在RISC-V生态系统中被广泛采用，以加速新兴工作负载，但跨不同内核实现和验证ISAX仍然缓慢且碎片化。现有框架仍然需要逐个内核的接口适配，而且一旦微架构或ISAX发生变化，差分测试往往就会失效。我们提出了LACE，这是一种LLM辅助的多智能体工作流，它将自然语言的ISAX意图转换为紧凑的两级IR（操作级和HDL任务级），在大型代码库上执行基于检索的局部RTL编辑，并通过与编译器无关的riscv-formal检查流程（假设RVFI可用或进行插桩）形成闭环。在四个嵌入式RISC-V内核上，LACE在我们的评估设置中将pass@1生成准确率从接近零提高到72.8%，同时改善了代码定位并减少了集成返工。LACE的代码可在 https://github.com/UMN-ZhaoLab/LACE 获取。

## Abstract
Domain-specific Instruction Set Architecture eXtensions (ISAX) are widely adopted in the RISC-V ecosystem to accelerate emerging workloads, but implementing and validating ISAXes across different cores remains slow and fragmented. Existing frameworks still require per-core interface adaptation, and differential testing often breaks once either the microarchitecture or the ISAX changes. We present LACE, an LLM-aided multi-agent workflow that translates natural-language ISAX intents into a compact two-level IR (operation-level and HDL task-level), performs retrieval-guided localized RTL edits over large repositories, and closes the loop with a compiler-agnostic riscv-formal checking flow (assuming RVFI availability or instrumentation). Across four embedded RISC-V cores, LACE raises pass@1 generation accuracy from near-zero to 72.8\% within our evaluation setup, while improving code localization and reducing integration rework. The code of LACE is available at https://github.com/UMN-ZhaoLab/LACE.

## 一、论文的核心问题与整体含义（研究动机和背景）

### 研究背景
- RISC-V 凭借其开放、模块化的 ISA 特性，成为 ASIP（专用指令集处理器）开发的天然基础，但**领域特定指令集扩展（ISAX）**在嵌入式与 IoT 工作负载加速中日益关键。
- 然而，ISAX 的**跨核实现与验证**依然缓慢且碎片化：不同处理器微架构（流水线深度、控制路径、接口风格各异）需要逐核人工适配。

### 核心问题
1. **跨学科知识鸿沟**：现有自动化框架（如 SCAIE-V、Longnail）依赖由硬件设计者编写的架构描述（DSL 风格），难以跨领域复用。
2. **未见内核的手动适配瓶颈**：将一个 ISAX 移植到不同核心仍需人工理解 core-specific 的解码、控制、数据通路和时序细节，且常被绑定到特定工具链或核心家族。
3. **LLM 直接用于 ISAX 设计存在三重差距**：
   - **抽象鸿沟**：ISA 描述的是高层语义，而 HDL 需要精确的低层实现细节；
   - **定位困难**：ISA 扩展需要在大型层级化 HDL 仓库中做精准修改，超过模型上下文窗口（如 cv32e40p 超过 243k token）；
   - **验证覆盖有限**：编译器定制的差分测试可移植性差，定向测试仅覆盖指令行为的窄子集。

### 整体含义
LACE 旨在提供**端到端的自动化 ISAX 设计闭环**：从自然语言意图出发，经过多智能体协同翻译、检索引导的局部 RTL 编辑，最终以编译器无关的形式化验证（riscv-formal）闭环，实现跨微架构的指令扩展快速集成。

## 二、论文提出的方法论

### 核心思想
LACE 采用**多智能体（Multi-Agent）架构**，模拟人工 ISAX 集成流程中"规格理解 → 任务分解 → 代码修改 → 反馈验证"的协作分工模式，同时引入**两级中间表示（Two-Level IR）**来解耦指令语义与微架构实现。

### 系统组成（六个智能体）
1. **Agent ① Operator Translator（操作翻译器）**：将自然语言 ISAX 规格转化为操作级 IR（Operations），涵盖接口操作符（如 RdInstr、RdRS1/2、WrRD、Rd/WrPC、Rd/WrMem、创建/读写自定义寄存器）和算术操作符（可组合的算术、位运算、移位、条件原语）。
2. **Agent ② Task Translator（任务翻译器）**：将操作级 IR 映射为具体 HDL 修改任务，利用三类元提示（meta-prompts）：
   - **架构无关描述**：专家设计的通用 ISAX 集成策略模板；
   - **架构特定提示**：描述流水线深度、控制路径等核心特性（如流水线核更新 PC 需冲刷后续级，而非流水线核只需取下一指令）；
   - **实例化过程**。
3. **Agent ③ Document Generator（文档生成器）**：自动提取目标 CPU 的流水线等架构信息，生成架构文档供其他智能体参考。
4. **Agent ④ RAG Supervisor（检索监督器）**：基于图结构的 HDL RAG 系统（复用 HDLxGraph 框架），将代码库表示为图（模块、always 块为节点，层级与数据流为边），提供：嵌入检索定位、受控图遍历、Cypher 查询三种工具；由搜索监督器分解查询并调度层级搜索、数据流搜索、通用搜索子代理。
5. **Agent ⑤ Verilog Writer（Verilog 编写器）**：基于检索上下文执行文件级精准 RTL 编辑（插入解码逻辑、寄存器端口等）。
6. **Agent ⑥ Feedback Agent（反馈智能体）**：分析 Verilator 编译/仿真结果，提供诊断反馈给 Writer 进行修正迭代。

### 验证流程
- **工具选择**：放弃差分测试（金模型正确性假设不成立、需编译器适配），改用 **riscv-formal**（基于 RVFI 断言 + Yosys sby 形式化验证），实现编译器无关的指令行为验证。
- **分步验证（Stepwise Verification）**：先在未修改的基线核上运行 riscv-formal 建立回归安全参考，再集成 ISAX 并重新验证，同时检查（i）原有 ISA 行为保持和（ii）新指令属性。
- 每次 HDL 修改先用 **Verilator** 做语法与仿真检查，再进入 riscv-formal 流程，形成"生成-验证-纠错"迭代循环。

### 技术工具
使用 LangChain 做智能体编排，ReAct 技术（Reasoning + Acting）结构化工具调用，GPT-4o（temperature 0.8）作为底层 LLM。

## 六、论文的主要结论与发现

1. **生成精度显著提升**：LACE 平均 pass@1 达 **72.8%**，而非智能体直接生成几乎为零（仅简单的 `rol` 指令在部分核心上成功）。复杂核心上所有 ISAX 的通过率仍高于 40%。
2. **搜索/定位能力增强**：Agentic RAG 在块级检索上平均 MRR 达到 **0.7714**，相对 BM25（0.4786）和 CodeT5+（0.3418）提升 **29.28%**（与 BM25 相比）以上，证明图结构搜索对大型 HDL 仓库定位有效。
3. **硬件开销可接受**：ISAX 集成平均增加面积约 10%，频率下降通常小于 10%；大核心相对开销更低；复杂多周期指令（sbox、load mul、sincos）带来更高面积/时序代价（如 sincos 在 PicoRV32 上面积 +69%）。
4. **与人类专家框架可比**：在 PicoRV32 上，LACE 的 ISAX 面积/频率开销与 SCAIE-V（人类专家设计）相当甚至更优（如 ijmp 面积 +2% vs +7%）。
5. **多跳验证提升收敛**：分步验证对简单设计引入少量额外开销，但对复杂 ISAX 显著减少总迭代次数，防止早期错误传播。
6. **跨核可移植性验证成功**：同一自然语言 ISAX 描述可自动适应非流水线（PicoRV32）、2/3/4 级流水线核心（e203、ibex、cv32e40x），支持了 IR 抽象的有效性。

## 七、优点（方法或实验设计上的亮点）

1. **两级 IR 设计巧妙**：将指令语义（操作级）与微架构实现（HDL 任务级）解耦，实现"一次规格、多核复用"，从根源上缓解 ISAX 生态碎片化。
2. **多智能体分工合理**：模拟人类协作流程，每个 Agent 职责单一、上下文窗口受限，避免单一大模型面对超大仓库的上下文溢出问题。
3. **Agentic RAG 创新**：利用图结构（层级+数据流）而不仅文本相似度做检索，辅以监督器驱动的多子代理并行探索，显著提升复杂 HDL 代码定位精度。
4. **验证方式务实**：选择 riscv-formal 而非差分测试，规避了金模型正确性和编译器适配两大难题，且采用"基线验证 → ISAX 验证"的分步策略降低回归风险。
5. **实验覆盖较全面**：横跨 4 种微架构 × 5 类指令 × 9 次重复，主实验、搜索消融、综合开销、收敛效率多维度评估。
6. **开源可复现**：代码在 GitHub (UMN-ZhaoLab/LACE) 公开。

## 九、未来研究方向与领域启示

### 后续可探索的方向（基于论文工作自然延伸）
1. **向更复杂微架构推进**：将 LACE 扩展到乱序执行、多发射、动态调度等高性能处理器。这需要更细粒度的流水线阶段建模，以及比 riscv-formal 更高效的非正式等价性检查手段。
2. **自动 RVFI 插桩**：当前 RVFI 的接入仍依赖人工工程。若能训练一个专门的 Agent 自动为任意 RISC-V 核心插入 RVFI 接口，将大幅提升 LACE 的“即插即用”能力。
3. **多语言/多抽象层次支持**：除 Verilog 外，支持 SystemVerilog、Chisel/FIRRTL 等现代 HDL，使框架能覆盖更广泛的硬件设计生态。
4. **指令级 IR 的标准库建设**：将 Operations 扩展成开源 ISAX 指令语义库，让设计者只需挑选组合而非从零描述，降低使用门槛。
5. **更智能的验证反馈**：将形式化反例（counterexample）转化为可读的 RTL 修改建议，甚至让 Agent 自行修复，进一步减少人工介入。

### 对硬件设计自动化领域的启示
LACE 的成功验证了“LLM + 多智能体 + 结构化检索 + 形式化验证”这一组合在硬件敏捷开发中的可行性。它提供了一条新的范式：**面向微架构迁移的指令扩展不再需要逐核手写 RTL，而是可以在高抽象层描述意图，由智能体自动完成从语义到实现、再到验证的闭环**。虽然目前限定在嵌入式 RISC-V，但该框架的“IR 解耦 + RAG 定位 + 形式化验收”思路，具有很强的可推广性。

## 十、总体总结

LACE 是一项针对 RISC-V 指令集扩展自动化设计的高质量系统工作。它以两级中间表示为核心抽象、以多智能体协作模拟人工集成流程、以图神经检索解决超长上下文的代码定位难题、以 riscv-formal 代替差分测试构建可靠的验证闭环，在四个异构嵌入式核心上实现了 72.8% 的平均端到端通过率，并验证了跨核移植、低硬件开销和高效收敛等关键性质。尽管在验证扩展性、RVFI 自动化、评估范围与模型泛化性上仍有明显不足，但该工作为 LLM 驱动的硬件敏捷设计提供了极具参考价值的系统级方案，也为未来“自动 SoC 定制”和“面向领域的计算系统快速生成”铺平了道路。
