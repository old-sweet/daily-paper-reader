## 摘要
大型语言模型在自动化Verilog RTL生成方面展现出潜力，然而最先进的多智能体系统在标准基准测试中仍停留在约95%的准确率。我们将这一上限归因于不完整的调试动作空间：现有系统限制了智能体可以检查的信号、可以查询的时间窗口，或两者都受限，从而将调试简化为对电路行为狭窄、预定视图的模式匹配，而非基于假设的根因分析。我们提出VeriTrace，一个多智能体系统，其Inspector智能体在完整的调试动作空间上运行，对信号选择、时间窗口边界和迭代深度具有独立控制。我们将这一能力称为智能体时间探索（Agentic Temporal Exploration），它使智能体能够形成关于故障原因的假设，查询波形以获取证据，并迭代地完善其理解，模拟人类验证工程师的探索过程。VeriTrace在VerilogEval-V2上实现了100%的Pass@1，成为首个在该基准上达到完美功能正确性的系统。在共享的Claude Sonnet 4.0骨干网络上，VeriTrace比最强复现基线高出+5.1%，表明调试智能体弥合了最终的准确率差距。

## Abstract
Large language models have shown promise for automated Verilog RTL generation, yet state-of-the-art multi-agent systems plateau at ~95% accuracy on standard benchmarks. We trace this ceiling to an incomplete debugging action space: existing systems restrict which signals the agent can inspect, which time windows it can query, or both, reducing debugging to pattern matching on a narrow, predetermined view of circuit behavior rather than hypothesis-driven root-cause analysis. We present VeriTrace, a multi-agent system whose Inspector agent operates over a complete debugging action space, with independent control over signal selection, time-window bounds, and iteration depth. This capability, which we term Agentic Temporal Exploration, enables the agent to form hypotheses about failure causes, query the waveform for evidence, and refine its understanding iteratively, mirroring the exploratory process of human verification engineers. VeriTrace achieves 100\% Pass@1 on VerilogEval-V2, the first system to attain perfect functional correctness on this benchmark. On a shared Claude Sonnet 4.0 backbone, VeriTrace outperforms the strongest reproduced baseline by +5.1%, demonstrating that debugging agency closes the final accuracy gap.

## 1. 核心问题与整体含义

- **背景**：现代数字硬件设计依赖 Verilog/SystemVerilog 等 HDL，人工编写 RTL 代码耗时且易错。大语言模型（LLM）已能生成语法正确的 Verilog，但单次生成缺乏仿真反馈，单智能体系统难以有效调试。
- **核心问题**：现有最先进的多智能体 RTL 生成系统（如 MAGE、VerilogCoder、ACE-RTL）在 VerilogEval-V2 上准确率封顶约 95%，作者认为瓶颈不是反馈信息不足，而是**调试动作空间不完整**——智能体只能检查预先指定的信号、只能在单一时间点查询，或两者皆受限，导致调试退化为“窄视图模式匹配”，而非假设驱动的根因分析。
- **整体含义**：作者提出“调试代理能力”（debugging agency）而非仅仅“更丰富的反馈”才是弥合最终准确率差距的关键。通过赋予 LLM 智能体类似人类验证工程师的完整时间探索能力，可以在标准基准上实现完美的功能正确性。

## 2. 方法论

- **核心思想**：模拟人类工程师调试 RTL 的方式——先写代码、仿真、查看可疑信号波形、形成假设、追溯逻辑块输入验证假设、迭代直到定位根因。VeriTrace 采用确定性多智能体流水线，新增一个专门的 Inspector 智能体，负责在**完整调试动作空间**中做假设驱动的诊断。
- **关键创新——Agentic Temporal Exploration（智能体时间探索）**：
  - Inspector 可独立控制三方面：**信号选择**（任意内部信号）、**时间窗口边界**（任意起止时刻）、**迭代深度**（查询次数）。
  - 按 ReAct 范式循环执行：思考（Thought）→ 行动（Action）→ 观察（Observation）。每一步根据推理决定再次查询（QUERY）还是终止（FINISH）。
  - 形式化描述：
    - 设仿真错误时间戳为 \(t_{err}\)，完整波形为 \(W\)。
    - 第 \(i\) 轮，Inspector 选择信号集 \(\sigma_i\) 和时间窗口 \([t_{start}^i, t_{end}^i]\)，调用波形追踪工具获得自然语言风格的波形快照 \(\omega_i = \text{TRACE}(W, \sigma_i, t_{start}^i, t_{end}^i)\)。
    - 随后推理 \(\tau_i, a_i = \text{THINK}(S, C, t_{err}, \omega_1, \dots, \omega_i)\)，其中 \(a_i \in \{\text{QUERY}, \text{FINISH}\}\)。
    - 终止后输出 Inspector Report \(R\)，包含行为失配诊断、推理依据和修复建议。
  - **诊断与修复分离**：Inspector 只负责诊断，RTL Debugger 负责代码修改，两者上下文窗口聚焦，避免混淆。
- **整体流程**：
  1. Testbench Agent 修改测试平台以导出全部波形。
  2. RTL Agent 生成初始代码，经语法检查与仿真。
  3. 若仿真失败，Inspector 执行时间探索，输出诊断报告。
  4. RTL Debugger 根据报告做局部修复，并通过“失配数单调递减”的检查点机制接受或回滚修改；修复后重新仿真，若仍有失配则再次调用 Inspector，直至 \(m(C)=0\) 或达到最大迭代 \(M=10\)。
- **效率设计**：Inspector 不读取完整 VCD 波形，只查询当前假设相关的信号与时间窗，从而降低 token 消耗（整体约降 18%）。
