## 摘要
硬件黑客竞赛已成为评估复杂片上系统（SoC）设计安全弱点的实用平台，同时促进了安全感知验证和工具开发。本文通过开放式硬件黑客竞赛对SoC安全验证进行了系统性研究，重点关注实用的漏洞分析策略、观察到的发现以及安全感知验证的经验教训。我们提出了一种多策略漏洞分析方法，结合了基于仿真的验证、形式化验证、lint分析、大语言模型（LLM）辅助的缺陷检测以及覆盖率引导的混合模糊测试。分析了具有代表性的漏洞发现，以说明不同技术如何揭示互补类别的安全缺陷，并得出了面向硅前安全验证的实用经验。最后，我们讨论了竞赛基准如何支持新兴硬件安全技术的可复现评估，并引导未来安全感知EDA研究。

## Abstract
Hardware hacking competitions have emerged as practical platforms for evaluating security weaknesses in complex System-on-Chip (SoC) designs while promoting security-aware verification and tool development. This paper presents a systematic study of SoC security verification through open-box hardware hacking competitions, focusing on practical vulnerability analysis strategies, observed findings, and lessons for security-aware verification. We present a multi-strategy vulnerability analysis methodology, combining simulation-based verification, formal verification, lint analysis, Large Language Model (LLM)-assisted bug detection, and coverage-guided hybrid fuzzing. Representative vulnerability findings are analyzed to illustrate how different techniques expose complementary classes of security flaws, and we derive practical lessons for pre-silicon security verification. Finally, we discuss how competition benchmarks can support the reproducible evaluation of emerging hardware security techniques and guide future security-aware EDA research.

## 2. 论文提出的方法论

**总体框架：多策略安全分析方法论，结合四阶段工作流**

### （1）四阶段分析流程

1. **环境构建与基线建立**：搭建设计环境，运行已有测试、形式化、lint流程建立基线
2. **漏洞候选生成**：每种分析策略分别生成漏洞候选
3. **候选筛选**：人工审查以去除工具错误、无效假设和重复发现
4. **漏洞确认与复现**：用自定义测试或形式化反例复现，映射到CWE，记录安全影响和缓解方案

### （2）五种互补的验证策略

| 策略 | 工具 | 核心机制 |
|------|------|----------|
| **模拟验证** | Synopsys VCS + DVSim框架 | 基于HJSON编排层自动化执行OpenTitan回归测试，分析失败用例、断言违例、超时和异常状态转换，区分安全相关失败与测试台错误 |
| **形式化属性验证（FPV）** | Synopsys VC Formal | 将安全需求转为SystemVerilog断言，穷举检查时序属性，用反例定位RTL缺陷 |
| **形式化安全验证（FSV）** | Synopsys VC Formal | 定义受保护源与未授权目的地，检测跨安全域的非预期信息流（如密钥位传播到软件可见寄存器） |
| **RTL Lint分析** | Synopsys VC SpyGlass Lint | 检测不全赋值、锁存器推断、位宽不匹配、未初始化寄存器、多驱动等结构问题，结合安全上下文筛选安全相关警告 |

### （3）关键设计理念

- **跨方法交叉验证**：各方法非独立运行，一个方法的结果指导另一方法（如lint警告→模拟验证；LLM发起的属性→形式化验证）
- **安全意图先行**：分析前明确受保护资产、信任边界、特权规则，区分功能失败与安全漏洞
- **自动发现需独立验证**：lint警告、LLM假设、断言失败均视为候选而非确认漏洞，必须追踪到RTL根因并用仿真迹线、形式化反例或自定义exploit复现

## 6. 论文的主要结论与发现

1. **安全意图是漏洞识别的关键**：功能失败≠安全漏洞，必须先明确受保护资产、信任边界和特权规则，才能正确解读测试失败或RTL代码。许多重要漏洞在正常操作下功能正确，但在未授权、错误或异常条件下违反安全需求。

2. **验证方法必须互补组合**：没有任何单一方法能全面覆盖所有SoC安全弱点——模拟适合复现可执行攻击序列，形式化适合时序属性和难达状态，静态分析提供可扩展的结构筛查，信息流分析直接检验机密性和完整性违规。

3. **现有验证基础设施需要安全感知引导**：传统回归测试主要覆盖预期行为，不针对未授权访问、恶意状态转换或异常错误条件。需要安全定向的激励生成和衡量安全相关状态/行为的覆盖率指标。

4. **自动化发现必须独立验证**：lint警告、LLM生成假设、断言失败和模糊测试异常只是候选。对LLM生成的结果尤其要警惕——语法有效的属性可能在语义上不正确，需要EDA工具作为验收标准。

5. **跨层分析对SoC级漏洞至关重要**：许多漏洞的激活依赖寄存器事务、固件操作、特权状态或门级网表转换，单模块RTL分析无法发现。

6. **工具自动化与并行化显著提升覆盖率**：大型SoC含众多IP和安全关键接口，手动分析不现实；自动化测试执行、日志收集、属性检查和结果分流可减少重复工作，多方法代理式LLM工作流比单技术顺序分析覆盖更好。

7. **竞赛基准具有长期研究价值**：漏洞RTL设计、已知bug集、安全属性、测试环境和exploit案例可作为可复用基准，支持信息流追踪、静态分析、符号执行、形式验证和LLM辅助检测等方法的公平比较。

## 7. 优点（方法/实验设计亮点）

- **多策略互补方法论设计**：将五种性质迥异的方法（动态仿真、形式化穷举、静态结构、AI推理、覆盖率引导模糊）整合为一个统一流程，且强调跨方法交叉验证，减少了误报的同时增强证据链可信度。
