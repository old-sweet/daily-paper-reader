## 摘要
现代集成电路（IC）日益复杂，使得功能验证成为主要瓶颈。主流的硬件形式化验证方法——模型检验，分别验证每个设计实例，且仅给出通过/失败结果，因此证明背后的推理被锁定在求解器启发式算法中，并在相关设计间被重复构建。交互式定理证明则能生成显式、可复用的证明工件，但将其应用于硬件仍 largely 依赖人工，需要专家在形式化、不变式发现和证明开发方面付出大量努力。在本文中，我们提出了CircuitProver，一个基于Lean 4的智能体验证框架，支持证明积累和参数化验证。CircuitProver自动将参数化硬件设计及其自然语言规范翻译为可执行的Lean 4模型，然后通过Lean反馈迭代地构造机器检查的证明，以确立硬件代码符合规范。证明轨迹和已验证的定理被提炼为可复用库，其中证明策略指导未来智能体的推理，已验证的引理支持跨相关硬件验证任务的形式化证明复用。我们进一步引入了首个用于评估智能体硬件定理证明的基准套件，涵盖多样化的参数化硬件设计、规范、证明任务和评估指标。在全部63个任务中，CircuitProver成功证明了所有基准，而普通智能体仅解决92.1%的任务，且平均需要两倍的证明轮次。消融研究表明，积累的证明知识减少了相关验证任务中的冗余证明构造，将证明长度缩短了16.3%，验证时间缩短了23.2%。

## Abstract
Modern integrated circuits (ICs) are becoming increasingly complex, making functional verification a major bottleneck. The dominant hardware formal verification methodology, model checking, verifies each design instance separately and exposes only pass/fail results, so the reasoning behind a proof stays locked inside solver heuristics and is repeatedly reconstructed across related designs. Interactive theorem proving instead yields explicit, reusable proof artifacts, but applying it to hardware remains largely manual, demanding expert effort for formalization, invariant discovery, and proof development. In this paper, we present CircuitProver, an agentic Lean 4-based verification framework supporting proof-accumulation and parameterized verification. CircuitProver automatically translates parameterized hardware designs and their natural language specifications into executable Lean 4 models. It then iteratively constructs machine-checked proofs through Lean feedback to establish that the hardware code complies with the specification. The proving traces and verified theorems are distilled into reusable libraries, where proving strategies guide future agent reasoning and verified lemmas support formal proof reuse across related hardware verification tasks. We further introduce the first benchmark suite for evaluating agentic hardware theorem proving, covering diverse parameterized hardware designs, specifications, proof tasks, and evaluation metrics. Across 63 tasks, CircuitProver successfully proves all benchmarks, while a vanilla agent solves 92.1% of them and requires twice as many proof rounds on average. Ablation studies show that accumulated proof knowledge reduces redundant proof construction across related verification tasks, reducing proof length by 16.3% and verification time by 23.2%.

## 2. 方法论

### 核心思想
- 将参数化硬件设计与自然语言规范自动翻译为 Lean 4 形式化表示，通过智能体迭代构造机器检查的证明，并将成功证明轨迹沉淀为两类可复用库（证明指导库 + Lean 检查定理库），实现跨任务的证明知识复用。

### 整体框架（三阶段）

**Phase I：硬件到 Lean 4 的自动形式化**
- 将参数化硬件设计表示为转移系统 D = (P, I, O, R, T)。
- 开发确定性的 Chisel-to-Lean 翻译器 T_impl: D → L_D，生成可执行的 Lean 4 语义模型。
- 保留设计参数、IO 接口、寄存器状态和状态转移行为；硬件信号和寄存器使用宽度感知的位向量类型建模。
- 通过小位宽穷举协同仿真（co-simulation）验证翻译正确性。

**Phase II：智能体硬件定理证明工作流**
- **Step 1（规范制定）**：形式化函数 F_spec: (L_D, S) → L_S，将自然语言规范转化为一组 Lean 4 正确性属性 {φ₁, φ₂, …, φ_k}，同样通过协同仿真验证。
- **Step 2（证明规划与脚手架构造）**：根据硬件行为类型分解证明任务。组合逻辑设计聚焦单周期计算正确性；时序设计先构造单步转移证明、再发现归纳不变量，连接逐步正确性与全局行为正确性。
- **Step 3（迭代定理证明）**：证明构造函数 F_proof: (L_D, L_S, P) → Π。智能体与 Lean 交互，根据返回的证明状态与错误信息反复修正证明脚本，直至 Lean 内核接受。核心公式为：

  ⊢_Lean Φ(L_D, L_S)

**Phase III：可复用硬件证明库**
- **证明指导库（Proof Guidance Library）**：将成功交互轨迹提炼为可复用的证明方案，记录如何分解证明、为何选择特定引理、如何根据反馈调整证明计划（包括失败修复原则）。
- **Lean 检查定理库（Lean-Checked Theorem Library）**：将轨迹中已验证的定理与其来源模块解耦，去除模块特定定义与信号名，用符号参数和通用接口重新表述，使定理能跨硬件设计实例化复用。

### 案例研究（Carry-Skip Adder 四阶段证明策略）
1. **设置证明**：局部命名生成模块的块操作、fold 步和初始状态。
2. **证明块正确性**：对 D = 2^b，证明 s_k = (A_k + B_k + C_k) mod D 且 C_{k+1} = ⌊(A_k + B_k + C_k) / D⌋（非跳越路径来自加宽加法，跳越路径利用全 1 传播条件）。
3. **全宽提升**：使用 fold 读回引理和基数闭包引理将块级递推组合为全宽 A+B+cin 结果。
4. **建立输出等价**：通过进位方程和 reverse-Horner 引理识别实现与规范的 sum/cout 字段，用记录外延性闭合证明。

## 6. 主要结论与发现

### 主结果
- **CircuitProver 在全部 63 个任务上成功证明（100%）**，vanilla agent 仅解决 92.1%（58/63）。
- 相比 vanilla agent：
  - 平均证明轮次减少 **50.0%**（9.2 → 4.6）
  - 验证时间减少 **23.2%**（658.9s → 506.2s）
  - 证明 LoC 减少 **16.3%**（129.8 → 108.6）
  - 输出 tokens 从 66.0K 降至 61.7K（算术类别 token 增加，因为解决了额外 3 个困难任务）
- **处理器级模块**：收益随设计复杂度增大。验证时间减少 56.8%、证明 LoC 减少 54.4%、输出 tokens 减少 55.9%、证明轮次减少 48.2%，相对于 Chicala/Stainless 证明 LoC 减少 57.8%。

### 消融发现
- **定理库**（可复用引理）：在有无指导的情况下分别将 40 轮预算内覆盖率从 60→63 和 58→63，帮助解决困难用例，提高可达性。
- **证明指导**（硬件感知引导）：将第 10 轮的解题数从 53 提升到 56，并将满覆盖所需轮次从 29 降低到 18，缩短搜索。
- 两者组合实现**满覆盖+最快收敛**（63/63 @ 18 轮），证明可复用引理与硬件感知指导发挥互补作用。

### 模型能力发现
- 证明覆盖率随模型能力提升：Haiku 4.5（31/63）→ Sonnet 4.6（47/63）→ Sonnet 5（60/63）→ Opus 4.8（63/63）。Opus 也是唯一全部解决的模型，且平均时间/ LoC/tokens/轮次最低。

## 7. 优点

1. **问题定位精准**：识别出现有模型检查与交互式定理证明之间的关键空白——自动化与可复用知识的结合，提出"证明积累型验证"新范式，具有较强的前瞻性。
2. **端到端自动化的完整框架**：从 Chisel 源设计到 Lean 4 模型、从自然语言规范到形式化属性、从证明规划到迭代验证，实现全流程自动化，大幅降低专家人工介入。
3. **双库设计巧妙**：证明指导库保存"怎么做"的推理策略，定理库保存"已知什么"的机器检查事实。前者加速搜索，后者提高可达性，两者互补，并通过具体 case study 清晰展示。
4. **参数化验证优势**：一次证明覆盖整个设计族（∀n, Spec ≡ Impl），不同于模型检查的逐实例验证，具有理论上的效率和表达优势。
5. **良好的实验设计**：首次引入智能体硬件定理证明基准，2×2 消融能清晰分离两类组件贡献，验证了可复用证明知识的实际价值。

## 8. 不足与局限

1. **翻译器覆盖有限**：Chisel-to-Lean 翻译器仅支持 Chisel 常用构造子集，未覆盖更广的 RTL 结构（如多时钟域、异步逻辑、时钟门控等），影响泛化能力。
2. **智能体依赖具体模型**：当前原型通过 Claude Code CLI 运行，实验仅使用 Claude 家族模型，未与 GPT、Gemini、DeepSeek 等模型进行交叉验证，存在潜在选择性偏差。
3. **算力报告缺失**：未报告 GPU 型号/数量、总计算量、能耗等资源数据，可复现性受限，也缺少对 token 总消耗的绝对度量。
4. **成本指标可比性瑕疵**：成本平均值基于不同成功子集计算（如算术类别 CircuitProver 额外解决 3 个困难任务，导致 tokens 更大），严格的公平可比性受损。
5. **翻译正确性依赖仿真**：使用小位宽穷举协同仿真验证翻译正确性，本质上无法覆盖任意参数的全部行为，存在未被检测到翻译错误的理论风险。
6. **与现有方法对比不均衡**：Chicala/Stainless 因前端问题大量失败，未能体现其定理证明能力；未与 Kami/Coquet 等更成熟的硬件定理证明框架或 SMT-based 方法进行深入对比。
7. **应用范围限制**：当前基准聚焦参数化 Chisel 设计，未覆盖工业级多模块完整 SoC 验证；协议验证（complex memory coherence、总线协议等）等更复杂的验证场景尚未触及。
