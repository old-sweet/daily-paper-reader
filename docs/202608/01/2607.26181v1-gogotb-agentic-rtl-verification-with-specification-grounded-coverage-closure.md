## 摘要
功能验证主导着集成电路（IC）前端工程工作，而任何一个遗漏至硅片的缺陷都可能引发代价高昂的重新流片。近期的大语言模型（LLM）为自动化该过程提供了新机遇，然而现有基于LLM的方法通过独立单轮调用生成各组件，缺乏共享上下文，导致接口不匹配未被检测，且报告的覆盖率与规格需求脱节。为应对这些挑战，我们提出GoGoTB，一个通过三个子系统实现端到端验证闭合的智能体框架：智能体执行控制层、可演化知识系统以及规格接地覆盖闭合。执行控制层在每个工具和阶段边界将确定性执行与LLM推理分离。知识系统按需调度方法论及设计特定专业知识。覆盖框架将每个覆盖仓锚定到具名规格行为，使每个残余缺口都有可诊断的根因和针对性补救措施。在8个寄存器传输级（RTL）设计上无需任何人工干预测试，GoGoTB实现了100%的环境生成成功率，平均行覆盖率98.4%、分支覆盖率97.2%、翻转覆盖率97.0%以及功能覆盖率83.2%。以往工作未能在相同基准上成功生成完整验证环境或实现有意义的覆盖率。

## Abstract
Functional verification dominates integrated circuit (IC) front-end engineering effort, and a single missed bug that escapes to silicon can trigger a costly respin. Recent large language models (LLMs) offer new opportunities to automate this process, yet existing LLM-based approaches generate each component through independent single-turn calls with no shared context, leaving interface mismatches undetected and reported coverage disconnected from specification requirements. To address these challenges, we present GoGoTB, an agentic framework that achieves end-to-end verification closure through three subsystems: an agentic execution control layer, an evolvable knowledge system, and specification-grounded coverage closure. The execution control layer separates deterministic enforcement from LLM reasoning at every tool and stage boundary. The knowledge system dispatches methodology and design-specific expertise on demand. The coverage framework anchors every bin to a named specification behavior so that each residual gap has a diagnosable root cause and a targeted remedy. Tested on 8 register transfer level (RTL) designs without any human intervention, GoGoTB achieves 100\% environment generation success and averages 98.4\% line, 97.2\% branch, 97.0\% toggle, and 83.2\% functional coverage. No prior work successfully generates a complete verification environment or achieves meaningful coverage on the same benchmarks.

## 2. 方法论：核心思想、关键技术细节

### 2.1 系统整体架构

- 输入：RTL源码、自然语言规格说明、可选参考模型。
- **八阶段流水线**，分四个阶段：
  - **规格分析**（S1–S2）：解析出设计档案与测试点清单；
  - **环境构建**（S3–S5）：由测试点构建覆盖模型、参考模型和测试平台；
  - **随机仿真**（S6–S7）：自适应随机种子策略下运行激励，累加代码/功能覆盖；
  - **覆盖闭合**（S8）：按根因分类诊断残留缺口并驱动定向修复。
- **三大子系统**，每个对应一个设计洞察：
  - 智能体执行控制层（解决可靠性）；
  - 可演化知识系统（解决知识注入）；
  - 规格接地覆盖闭合（解决覆盖可追溯性）。

### 2.2 智能体执行控制层（三层架构）

- **Layer 1：工具调用拦截**——三个步骤顺序执行：
  - *Guard*：检查LLM是否调用当前阶段正确的工具，阻止错误调用；
  - *Structuring*：将原始编译器/仿真器输出转换为结构化诊断，使LLM基于根因推理；
  - *Validation*：会话边界验证产物完整可编译后方可关闭；同一命令连续失败3次则注入重定向提示打破循环。
- **Layer 2：质量门（Quality Gates）**——先运行无LLM参与的自动修复（Auto-Repair），再按严格度递进通过三个门：
  - *Hard Gate*：编译成功与必备产物，失败即阻断；
  - *Soft Gate*：测试点完整性与信号名一致性，早期阻断、后期降级为警告；
  - *Advisory Gate*：语义审查，不阻断进度。
- **Layer 3：失败恢复**——按错误类别注入针对性反馈，重试次数越阈值时按L1→L4升级修复范围：
  - L1（最小补丁）→ L2（读全跨文件上下文）→ L3（重构问题组件）→ L4（回退到最小正确实现）。
- **边界强制（横切约束）**：每个阶段只能访问所需产物；RTL源码和参考模型对后续阶段不可变；参考模型只从规格推导，不看见RTL实现——确保仿真不匹配必然指向真实设计缺陷而非被破坏的预言机。

### 2.3 可演化知识系统（双库架构）

- **技能库（Skill Library）**：存放10个方法论模块（测试平台构建、测试规划、覆盖闭合、RTL分析等）；通过阶段级映射**确定性调度**；仅先传目录，按需加载全文；新设计类别只需新增知识文件即可扩展。
- **参考库（Reference Library）**：存放已验证设计的RTL、规格、测试平台和测试点；按三层结构相似度打分：
  - 高度匹配 → 作为直接模板；
  - 部分匹配 → 作为风格指南；
  - 低匹配 → **完全抑制注入**（宁可无参考，不给误导参考）。
- 两个库的调度均不涉及LLM判断，确定性实现。

### 2.4 规格接地覆盖闭合

- **核心思想**：覆盖模型质量在建模时即被决定——每个覆盖仓在仿真前锚定到具名规格行为，缺口因此有有限根因集合。
- **测试点分解（S1–S2）**：七个行为维度——D1数据边界、D2控制流、D3时序约束、D4 FSM状态迁移、D5协议合规、D6错误注入、D7微架构交互。
- **覆盖模型与仿真（S3, S6–S7）**：每个覆盖仓从信号值划分转化为携带行为声明的断言式覆盖元素。
- **缺口诊断与闭合（S8）**：**七类根因分类**表及对应补救：
  - 激励缺口 → 定向测试生成；
  - 序列缺口 → 多事务定向测试；
  - 交叉洞 → 约束精化；
  - 状态未达 → 状态路由序列；
  - 时序依赖 → 周期精确激励；
  - 跳变缺口 → 边沿条件测试；
  - 种子不足 → 扩展种子。
- **停机条件**：连续两轮无改进即终止；结构不可达仓从分母剔除；签字报告逐一记录每个已覆盖仓的证据与每个残余缺口的根因处置——完全可审计，不会有缺口被静默丢弃。

## 6. 主要结论与发现

- **执行控制架构是收敛的关键**：三层执行控制使8设计 × 7 LLM全部环境生成成功（5m30s–48m10s）；UVM 2因缺乏强制与迭代机制在所有8设计上全部失败（0% SRG），差异源于架构而非模型能力。
- **规格接地覆盖模型更丰富且更可诊断**：AES上GoGoTB产出6个覆盖点 + 2个交叉，UVM 2仅3个覆盖点 + 1个交叉，且每个GoGoTB覆盖点映射到具名规格行为，每个UVM 2仓只是无行为声明的信号数值区间。
- **平均覆盖率**：行98.4%、分支97.2%、翻转97.0%、功能83.2%；5个设计行覆盖≥99%，全部设计分支覆盖>91%。
- **知识缺失可导致静默覆盖归零**：UART上禁用知识系统时，环境编译仿真无错但全部功能仓为0%；注入三个域契约后功能覆盖升至75.3%——证明故障是知识缺口而非模型能力缺口。
- **规格接地闭合可原则性收敛**：I2C功能覆盖从56.0%经多轮根因诊断迭代升至84.1%（+28pp），每轮决策都源于覆盖仓的根因标签而非通用重试。
- **主要瓶颈在定向测试生成**：残余缺口以激励缺口和序列缺口为主（I2C 24个残余中占16个）——系统能正确定位"测什么"，但LLM智能体尚不能可靠生成"怎么测"的复杂多步骤协议场景。

## 7. 优点

- **架构性分离洞见清晰**：将"LLM推理"与"确定性强制"架构性分离，可靠性依赖控制架构而非任一具体模型，这是与所有前作的根本差异。
- **覆盖可追溯性设计完整**：从测试点分解（7维度）→ 覆盖仓锚定（具名规格行为）→ 缺口分类（7类根因）→ 定向补救 → 签字报告全程可审计，闭环有理论依据。
- **边界强制保障可信性**：参考模型隔离保证仿真不匹配必然指向DUT缺陷，杜绝预言机污染导致的假阴性。
- **知识注入的确定性调度**：技能库阶段映射 + 参考库相似度门控均不依赖LLM判断，且低匹配时主动抑制注入（宁可无参考不给误导），这是细腻的设计决策。
- **实验设计有说服力**：7个LLM的跨模型验证、知识开关的对照实验、覆盖闭合过程的根因追踪，均紧密支撑核心主张。
