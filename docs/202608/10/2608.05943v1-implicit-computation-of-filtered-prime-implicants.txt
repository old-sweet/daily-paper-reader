# Implicit Computation of Filtered Prime Implicants 

Edward Liem and Clemens Dubslaff 

Eindhoven University of Technology, The Netherlands 

{e.liem,c.dubslaff }@tue.nl 

Abstract. Prime implicants (PIs) are central in computer science, with applications in logic minimization, diagnosis, explainable formal methods and AI. Algorithms for the computation of PIs were first-and-foremost considered on the full input space, not considering the case where the input space might be constrained by context or structural dependencies. To filter out those PIs that do not fulfill the constraints, existing methods rely on an explicit post-processing step after computing all PIs, which leads to scalability issues due to the number of PIs being exponential. We propose end-to-end symbolic algorithms that implicitly represent the set of PIs under side constraints. For this, we extend the prominent Coud-ert–Madre method based on decision diagrams and implement a modular tool chain that separates decision-diagram construction, PI computation, and filtering. 

## 1 Introduction 

A prime implicant (PI) of a Boolean function is a minimal term as conjunction of literals implying the function. Prime implicants play an important role in many areas of computer science: in circuit design, we may ask which terms suf-fice to realize an output; during fault diagnosis, the maximal set of components allowed to fail are important; a user may want to know which features determine a prediction or yield an effect of a system to emerge. All three questions boil down to computing sets of prime implicants. Minimal sum-of-products for cir-cuits via PIs have been prominently considered by Quine and McCluskey [22,19], followed by further applications to limit the search space in two-level logic min-imization [1,5]. In model-based diagnosis, PIs coincide with minimal conflicts and minimal supports [14,15]. In the emerging field of formal explainable formal methods and artificial intelligence (AI) they are the mathematical definition of an abductive explanation [24,13] or feature cause [9,10]: a minimal set of feature values that entail an effect, independently of all remaining features. What unites these applications is also what makes them hard. A Boolean function may possess exponentially many PIs. Deciding whether a shorter im-plicant exists given a PI candidate is Σp

Also within PI-based explanations, constraints naturally arise when the set of inputs are restricted to valid ones, ruling out all PIs that only cover invalid inputs [24,4,9]. Therefore, implementations scaled only to small-scale instances of constrained PI-computations [9,10,11]. In this paper, we tackle this problem by establishing an end-to-end sym-bolic algorithm to compute filtered PIs, realized through symbolic filters on the implicit representation of all PIs. For this, we rely on the prominent decision-diagram algorithm to compute PIs by Coudert and Madre [6] and extend it by carefully operating on the implicit PI-set representation. We present three vari-ants of filters to solve constrained PI problems: an existential filter that only includes PIs that touch a valid input, useful for computing feature causes [10], a universal filter that requires the PI only covering valid inputs, which has nat-ural applications for constrained abductive explanations [4] and a stronger form of feature causes, and a subset filter that is useful to compute offset PIs and most general feature causes [17,9]. 2.3 Meta-products 

A Boolean function over variables X is unable to represent sets of partial assign-ments over X. Coudert and Madre define the notion of a meta-product (MP) to encode a set of partial assignments as Boolean functions [6]. Observe that for an assignment p ∈ ∆X , an element x ∈ X may be p(x) = 1, p(x) = 0, or p(x) = ∗. 2.4 Binary Decision Diagrams 

Binary decision diagrams (BDDs) offer a representation for Boolean functions. A BDDs is an acyclic, directed graph G = ( T, N, λ, δ, ρ ) such that 

– ∅ ⊂ T ⊆ { 0, 1} is a set of terminals ,

– V is a finite set of vertices , where V ∩ T̸ = ∅,

– λ : V → X is a labeling function ,

– δ : ( V × B) → (V ∪ T ) is a decision function , and 

– a root ρ ∈ (V ∪ T ). The semantics JuK of some u ∈ (V ∪ T ) of BDD G = ( T, N, λ, δ, ρ ) is recursively defined as follows: 

J0K = false 

J1K = true 

JvK = ( λ(v) ∧ Jδ(v, 0) K) ∨ (λ(v) ∧ Jδ(v, 1) K) for v ∈ V

A BDD G is ordered if for any node v ∈ V such that λ(v) = xi and vertex 

u ∈ { δ(v, 0) , δ (v, 1) } such that λ(u) = xj , we must have that i < j . Moreover, an ordered BDD G is reduced if there does not exist two distinct isomorphic subgraphs of G. Henceforth, we assume all BDDs are reduced and ordered. By fixing a variable ordering, BDDs offer a canonical representation of Boolean functions [2]. Thus, we assume a fixed ordering over variables, and for every Boolean function f we have a BDD G = ( T, N, λ, δ, ρ ) such that JρK = f . We therefore may write f to also denote its uniquely defined BDD. Additionally, for non-constant Boolean functions f , where λ(ρ) = x it follows by Shannon decomposition that fx = Jδ(ρ, 0) K and fx = Jδ(ρ, 1) K.BDDs for meta-products. ## 3 Filtering Assignment Sets 

In this section, we present algorithms that operate on the structure of meta-products to filter and remove partial assignments not meeting certain criteria. Given a meta-product BDD P representing a set of assignments P ⊆ ∆X and a BDD f , we remove assignments in P and return an meta-product BDD Q ≡ Q

such that Q ⊆ P and for all q ∈ Q, the predicate Φ(q, f ) holds. In particular, we define three filtering predicates Φ = {∃ , ∀, ⊇} :

∃(q, f ) = ∃u ∈ Jf K. u ∈ JqK

∀(q, f ) = ∀u ∈ Jf K. u ∈ JqK

⊇(q, f ) = ∀u ∈ JqK. u ∈ Jf K

Figure 2 illustrates the idea behind each filtering predicate. The cover of f is shown in purple, and the cover of valid assignments in green. For the ∃ predicate, we keep assignments for which there is at least one instance in f that is covered (Figure 2a). In the case of our ∀ predicate, we eliminate assignments that do not completely cover f (Figure 2b). In contrast, filtering with predicate ⊇ keeps assignments that are completely subsumed by the cover of f (Figure 2c). We first present Algorithm 2 to filter a set of assignments based on the ∃

predicate. Given a meta-product BDD P such that P ≡ P for some P ⊆ ∆X , and a BDD f , we traverse P and trim branches not satisfying the ∃ criteria. Along a path starting from the root meta-product BDD to a 1 terminal, we update 

f accordingly. In particular, at a given node in P associated with variable xi,whenever xi does not occur in the assignment, i.e. oi is false , the cover of the assignment may intersect with either the positive or negative cofactors of f ,and thus we recurse on both sides and union both resulting sets. Otherwise, if our assignment contains xi we consider the negative cofactor of f , and if our assignment contains xi we recurse on the postive cofactor of f .

## 4 Feature Causality 

One application for filtering assignment sets is in the context of explaining con-figurable systems. Given a set of features and a set of total assignments over these features representing some effect, feature causality identifies the features that are the reasons for exhibiting the effect [9]. The classical approach for com-puting these causes is through existentially filtering prime implicants. We here demonstrate the use of our implicit filtering algorithms to compute a generalized notion of feature causes [10].

Moreover, we may compute the set of most general covers using the implicit techniques we introduced in the last section. Most-general causes filter those causes that are covered by another cause and thus would serve as shorter ex-planation for the effect. For computing such covers, we present a generalization based on ∀-filtering in Algorithm 6, which removes primes covered by other primes. This is done by taking a candidate assignment and extracting a more general assignment w.r.t. space f . The resulting output is an equivalence class of causes that are cannot be further generalized. To obtain all general causes, we run Algorithm 7. The idea is to pick a candidate prime (line 2), generalize them to obtain the most general equivalence class covering this candidate prime, and add these general causes to the set Q (line 3). Afterward, we remove the remaining products that cover the same space in f as our computed equivalence class cover and repeat the procedure until we have no more candidates.

Example Use Case. Using our tools, we provide an example of computing the feature causes from the email example found in [10], also provided within the source code repository of our tools. 

Example 1. Assume we are given the following files: File Name Description A list of feature names, each on their own line. A DNF formula representing the ON-set as On we witness, where each disjunct/product is on its own line. A DNF formula representing the configuration space as the care set Valid .

email.fs on.dnf valid.dnf 

From these files we can obtain the set of effects Effect = Valid ∩ On and non-effect NEffect = Valid \ Effect . First, we obtain the BDDs from the formula files. Running the following command gives the file on.bdd and valid.bdd .      

> bddOp ./ email . fs ./ on . dnf ./ on . bdd bddOp ./ email . fs ./ valid . dnf ./ valid . bdd

Since we are computing feature causes, we must first obtain the relevant BDDs for prime computation. In particular, given Valid and On , we must find the primes of Valid ∪ On . We then find candidate causes using the primes algorithm.           

> bddOp -- not ./ valid . bdd ./ nValid . bdd bddOp -- or ./ nValid . bdd ./ on . bdd ./ nV_or_e . bdd primes ./ email . fs ./ nV_or_e . bdd ./ candidateCauses . bdd

To obtain the feature causes, we use our Filter ∃ algorithm on the candidate causes over the Effect = Valid ∩ On configuration space.         

> bddOp -- and ./ valid . bdd ./ on . bdd ./ effect . bdd pfilter -- exists ./ candidateCauses . bdd ./ effect . bdd ./ fCauses . bdd

As the meta-product BDD implicitly represents the causes, we may obtain a list of causes using the i2e tool:   

> i2e ./ email . fs ./ fCauses . bdd

We obtain the following output after the procedure, comprising all the fea-ture causes and explicitly listing them as partial assignments: 

rsa encrypt ~caesar aes 

Going further, one may compute the set of the most general cover:        

> generalize ./ email . fs ./ valid . bdd ./ on . bdd ./ fCauses . bdd ./ genCauses . bdd i2e ./ email . fs ./ genCauses . bdd

This yields the following output: 

encrypt ~caesar 

Feature Causality Convenience. Alternatively, for directly computing fea-ture causes without manually executing the above pipeline, one may use the dedicated fcause tool to obtain the feature causes:       

> fcause ./ email . fs ./ valid . bdd ./ on . bdd ./ fCauses . bdd i2e ./ email . fs ./ fCauses . bdd

These commands yield the same output as the pipeline illustrated above. 6 Conclusion 

In this paper, we have presented algorithms over the structure of meta-product BDDs to filter sets of assignments implicitly based on various criteria, exempli-fied by existential, universal, and suset-filtering. Using the use case of feature causality, we show how our techniques enable a completely symbolic computation pipeline for deriving feature precauses and the set of most general causes. We offer a software toolkit of our methods, allowing for BDD construction, implicit computation of prime implicants, and filtering symbolic assignment sets. Future work includes an empirical evaluation of our algorithms by compar-ing our fully symbolic pipeline with the partially symbolic approach for feature causes [10] and integrate performant BDD-based techniques to compile care sets and ON-sets, e.g. required for symbolic feature model and effect set representa-tions [12,8].
