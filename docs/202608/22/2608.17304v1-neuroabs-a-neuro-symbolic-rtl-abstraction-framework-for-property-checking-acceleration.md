## 摘要
形式验证是确保硬件设计功能正确性的关键技术。在属性检查中，一个关键挑战是如何在面对日益复杂的RTL设计时高效地证明用户指定的属性。为了解决这一挑战，通常采用抽象技术来降低系统复杂性并加速验证过程。然而，先前的RTL抽象方法要么需要大量人工努力，要么依赖于缺乏灵活性的基于规则的技术。本文介绍了NeuroAbs，一种用于RTL抽象的神经符号框架。NeuroAbs首先使用LLM辅助的RTL分析来识别适合抽象的信号。然后，它将基于LLM的抽象与基于AST的符号RTL表示相结合，以更好地使生成的抽象与预期转换对齐。每个抽象的正确性通过可满足性模理论（SMT）求解来检查。如果抽象过于粗糙以至于无法成功证明，NeuroAbs应用反例引导的抽象细化（CEGAR）来迭代改进模型。实验结果表明，NeuroAbs在一系列验证任务中显著提高了硬件属性检查的效率。

## Abstract
Formal verification is a crucial technique for ensuring the functional correctness of hardware designs. In the context of property checking, a key challenge is how to efficiently prove a user-specified property in the face of increasingly complex RTL designs. To address this challenge, abstraction techniques are often employed to reduce system complexity and accelerate the verification process. However, prior RTL abstraction methods either require significant manual effort or rely on rule-based techniques that lack flexibility. This paper introduces NeuroAbs, a neuro-symbolic framework for RTL abstraction. NeuroAbs first uses LLM-assisted RTL analysis to identify signals suitable for abstraction. It then combines LLM-based abstraction with an AST-based symbolic RTL representation to better align the generated abstraction with the intended transformation. The soundness of each abstraction is checked using satisfiability modulo theories (SMT) solving. If the abstraction is too coarse for a successful proof, NeuroAbs applies counterexample-guided abstraction refinement (CEGAR) to iteratively refine the model. Experimental results show that NeuroAbs significantly improves the efficiency of hardware property checking across a range of verification tasks.

## 2. 论文提出的方法论

### 核心思想
NeuroAbs 采用“神经符号”（neuro-symbolic）流程：神经组件（LLM）负责从设计说明书、验证场景和属性描述中提出抽象候选，符号组件（AST、SMT、CEGAR）负责约束、验证和细化抽象，确保抽象是可靠的过近似（over-approximation）。

### 关键技术细节

1. **LLM 辅助的信号分析（Signal Analyzer）**
   - 输入：设计规格、验证场景描述、信号定义、属性或环境设置。
   - 采用思维链（Chain-of-Thought）提示，分两步：先理解信号行为，再映射到 RTL 中的实际信号名。
   - 输出：与场景相关的候选信号及其建议的恒定值（如将 `op` 固定为 `OP_ADD`），并给出理由和预期影响。
   - 结合静态分析（如常数传播）进一步定位受影响的 RTL 逻辑区域。

2. **AST 定位 + LLM 抽象生成（Abstractor）**
   - 将 RTL 转换为 AST 符号表示，按候选信号定位语句级 AST 节点，并追溯其外层结构（如 `always`、`case` 等）作为上下文。
   - 第二个 LLM（Abstractor）只被允许在指定 AST 节点对应的语句区域内进行重写，避免无约束的自由文本编辑。
   - 通过少样本学习（few-shot learning）提供原语句/抽象语句的示例，提高生成质量。
   - 抽象示例：将 `alu_result` 中与目标属性无关的分支替换为 X（未知值），保留与 ADD 相关的计算。

3. **SMT 可靠性检查（Soundness Checking）**
   - 对每个重写语句验证过近似约束：
     - 基本规则：`∀V, S(V) ⇒ Ŝ(V)`，即原语句的所有行为必须被抽象语句允许。
     - 对 X 值的处理：将每个 X 编码为存在量词约束的新变量，规则扩展为：
       `∀V, ∃Y, S(V,Y) ⇒ Ŝ(V,Y)`
   - 只有通过 SMT 检查的重写才会被保留；未修改的语句保持不变，从而保证整个抽象模型是原模型的过近似。

4. **自定义 CEGAR 流程（R-CEGAR）**
   - 若抽象模型上产生反例，先对反例进行归约/泛化（counterexample reduction），找出真正导致违反属性的抽象语句。
   - 定位对应 AST 节点并将这些语句恢复为原语句，进行迭代细化。
   - 算法流程（Algorithm 1）：反复执行属性检查 → 若存在反例则泛化 → 判断是否有无效抽象语句参与 → 若有则细化，否则返回 UNSAFE；若无反例则返回 SAFE。

## 6. 论文的主要结论与发现

- NeuroAbs 能够高效生成高质量、场景感知的 RTL 抽象，并在 SMT 检查下保持过近似可靠性。
- **形式证明加速**：
  - 与 AVR 集成时，总体验证运行时间提升 **44.89%**（均值 607.03s → 334.56s）。
  - 与 RIC3 集成时也有提升（均值 18.71s → 16.94s），但幅度较小，因为 RIC3 本身在这些案例上已经很快。
- **BMC 探索能力**：
  - 在相同时间内，NeuroAbs 使 BMC 达到更深的展开深度（如 Piccolo 从 109.36 增至 125.36；Flute 提升 75.98%，以 5668.58s 即可达到基线 23600s 的深度）。

- NeuroAbs 可支持多种 RTL 抽象类型：一元/二元运算、三元运算、case 语句、循环、always/initial 块等。

## 7. 优点

- **自动化程度高**：仅需设计规格、验证场景和属性，即可生成合适合抽象，减少了人工干预。
