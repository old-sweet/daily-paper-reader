## 摘要
寄存器传输级（RTL）仿真被广泛用于硬件制造前的测试。为了测试与安全相关的信息流属性（如机密性和完整性），可以在设计中自动添加污点逻辑来跟踪信息如何流经设计。然而，由现有最优技术（如CellIFT）插桩的污点逻辑使得基于仿真的测试代价高昂：在我们对Mega-BOOM（136K单元）的评估中，它使插桩后的设计规模达到原始单元数的5.81倍，并导致143.72倍的仿真减速。污点逻辑可以简化以提高仿真速度，但这将不可避免地牺牲其精确性。这种轻量级、不精确的污点逻辑会引入误报，并可能最终导致检查这些误报需要更大的开销。本文探讨了一个研究问题：为了克服误报的开销，设计中究竟在哪些位置需要精确性。我们提出了CEGAR-T，一个自动综合污点逻辑的框架，它在保证无误报（相对于精确的CellIFT基线）的同时，最小化污点逻辑插桩开销。我们已实现CEGAR-T，并针对开源RISC-V内核上的时序侧信道安全的安全指令集问题进行了评估。在所有评估的内核上，CEGAR-T将插桩和仿真开销的几何平均值分别从5.64倍降至1.42倍、从34.65倍降至1.79倍，且未损害CellIFT基线的精确性优势。

## Abstract
Register-Transfer Level (RTL) simulation is widely used to test hardware before it is fabricated. To allow testing for security related information flow properties, such as confidentiality and integrity, taint logic can be automatically added to the design to track how information flows through it. However, taint logic instrumented by the state-of-the-art, such as CellIFT, makes simulation-based testing prohibitively expensive: On our evaluation of Mega-BOOM (136K cells), it increases the instrumented design to 5.81x the original cell count and causes a 143.72x simulation slowdown. The taint logic could be simplified to improve simulation speed, but it will inevitably trade off its precision. This lightweight, imprecise taint logic will introduce false positives and may eventually result in even more overhead to check these false positives. This paper explores the research question of where precision is actually needed in the design to overcome the overhead of false positives. It presents CEGAR-T, a framework that automatically synthesizes taint logic that minimizes the taint-logic instrumentation overhead while guaranteeing no false positives (relative to the precise CellIFT baseline). We have implemented CEGAR-T and evaluated it on the safe instruction set problem for timing side-channel security across open-source RISC-V cores. Over all evaluated cores, CEGAR-T reduces both instrumentation and simulation overhead, in geometric-mean, from 5.64x to 1.42x and from 34.65x to 1.79x, respectively, without compromising the precision benefit of the CellIFT baseline.

### 1. 核心问题与整体含义（研究动机与背景）

- **背景**：硬件设计在流片前需要在 RTL 层面进行安全测试，其首要目标是尽早发现可能破坏机密性或完整性的微架构侧信道漏洞（如 Spectre、Meltdown 等）。一旦漏洞流入芯片，补丁成本极高，因此预硅（Pre-Silicon）验证十分重要。
- **信息流追踪与污点分析**：基于污点分析的信息流追踪是预硅安全验证的常用手段。它用源（source）表示秘密数据，用汇（sink）表示应受保护的状态或可观测输出，通过插桩污点逻辑来动态追踪秘密数据是否影响关键信号，以此判断设计是否满足非干扰（NI）语义。
- **核心矛盾**：
  - **纯精确方法代价过高**：以 CellIFT 为代表的最新技术在 Mega-BOOM（136K 单元）内核上使得电路规模膨胀至原始规模的 5.81 倍、仿真速度降低 143.72 倍，严重阻碍了大规模验证；
  - **纯轻量方法会引入大量误报**：简化污点逻辑虽能提升仿真速度，但引入了大量假阳性（spurious counterexamples），检查这些误报反而造成更大的端到端开销。
- **本文核心研究问题**：在设计中，**究竟哪里真正需要污点逻辑的高精度**，才能在消除误报开销的同时尽可能保持污点跟踪的轻量化？
- **整体贡献**：提出 **CEGAR-T**，一个全自动化、反例引导的污点逻辑优化框架。它把“从哪里精确化”（选择提纯模块）和“如何精确化”（选择精化程度）全部转为系统性的优化求解问题，在保持与 CellIFT 基线同等精度（无误报）的前提下大幅降低插桩与仿真开销，使大规模预硅安全验证更具实用性。

### 2. 方法论：核心思想与技术细节

#### (a) 总体框架：CEGAR 循环

- 采用“反例引导的抽象精化”范式：先使用最不精确（最轻量）的污点逻辑，仿真检测到污点到达汇（counterexample，cex）时，检查该 cex 是否是“虚假”的（即满足非干扰语义但实际上不应产生信息泄漏）；若是虚假就精化当前污点逻辑，迭代往复，直至不再产生假阳性。
- CEGAR-T 将“Where/How to refine”两个问题均转化为可自动求解的优化问题，区别于 Compass 等工作中启发式搜索 + 人工判断的做法。

#### (b) 精度的形式化定义（How to refine 的基础）

- **非干扰语义**：要求秘密输入变化不会影响汇输出（在公共输入固定条件下），形式化为：
  - 组合逻辑：∀Xp, Xs, Xs′: f(Xp, Xs) = f(Xp, Xs′)；
  - 时序逻辑：对任意等长输入迹，若每个周期公共输入相同，则最终 sink 输出相同。
- **按 taint assignment 的精度**：给定一个 taint 赋值（哪些输入被标记为秘密），taint 逻辑精确当且仅当它的输出等于真实 NI 脆弱性谓词，即 ∃Xs′: f(Xp, Xs) ≠ f(Xp, Xs′)。
- **最精确（precise）taint 逻辑**：在所有可能 taint assignment 下均精确。可按 taint 赋值最小项展开的方式构造，等价于文献中已有的精确逻辑。

#### (c) 精化格（Refinement Lattice）

- **根节点**：最粗略但实用的污点逻辑，即输出 taint = 输入 taints 的 OR（不带任何值依赖信息）。
- **精化算子**：给定 taint 赋值 τt，计算阻塞条件 Rτt(Xp)——即公共输入为何种值时秘密无法影响输出；将原 taint 逻辑与该阻塞条件取反求交，得到更精确版本（消除该 taint 赋值下的虚假传播）。
- **精化格的节点**：由根出发通过反复应用精化算子得到的各种候选 taint 逻辑；最精细的节点是精确 taint 逻辑。精化之间的交换性（commutativity）允许对同一模块按多个反例条件做批处理精化。
- 相比基于精确逻辑离线化简得到的候选逻辑，这种格式允许对“每个 taint assignment”生成不同精细程度的候选，搜索空间更细致（如 AND-3 门的格含 64 个节点）。

#### (d) Where to refine：Max-SAT 优化

- **核心问题**：给定一个虚假反例，选择哪些模块做精化，且求最小精化集合（以最小改动消除假阳性）。
- **关键步骤**：
  1. **识别候选模块（Refinement Candidate Set）**：在当前粗精度 taint 逻辑和精确参考 taint 逻辑下分别做仿真；某模块只要任一时刻“当前为 tainted、精确参考为 untainted”，就加入候选集合。
  2. **带使能条件的精化编码**：不能简单让变量 rf 强制模块输出 0——因为其上游 taint 可能也已被消减，输入 taint assignment 会随之改变。因此构造使能条件 Sf(Xt)（在给定具体输入取值、给定当前到达的输入 taints 下，当前 taint 逻辑是否与参考不一致），用门控多路选择器实现“仅在虚假 taint 发生时允许精化生效”。
  3. **Max-SAT 求解**：整个组合逻辑编码为布尔约束，强制汇在最后一拍时 taint=0，同时最小化被精化的模块数。求解结果同时决定哪些模块精化、每个模块按何种 taint assignment 做精化。

#### (e) 两种互补的时序精化算法

| 算法 | 思路 | 优点 |
|---|---|---|
| **Unroll Approach** | 将整个反例迹（多周期）完全展开，一次性构建 Max-SAT 实例做全局优化 | 对单个反例得到最小精化集合，精化总数更少 |
| **Single-Frame Approach** | 以单周期为单位做逐步精化：依次处理每个时间帧，逐步清除下一帧中虚假 tainted 的 DFF 状态；每处理一帧重新仿真；不止针对最终 sink，同时也清洗跨周期传播的虚假状态 | 避免了大规模展开引起的求解开销，显著提升可扩展性 |

#### (f) 虚假性检查的两阶段方法

- 对一个 cex 先运行**精确参考污点仿真**（快速、盲目但不完整）；若参考仿真也标记为 tainted，再用 **SAT 求解 unrolled self-composition**（完整但更慢）确认是否为真实信息泄漏。两种检查结合保证了 cex 判定的高效性与完备性。

#### (g) 工程实现选择：Word-level CellIFT

- 以 CellIFT 为基础，改为**词级粒度**（每个 word 一个 taint bit，而非每 bit 一个），显著减少 taint 状态数量；在设计格和每 cell 类型时可预计算、存储各候选结点逻辑，线上精化只需“热切换”。
- 使用 Yosys 做前端解析，用 Z3 的优化引擎求解 Max-SAT。

### 6. 主要结论与发现

- **CEGAR-T 达到目标精度要求的水平**：在几乎所有保留测试中，CEGAR-T（Frame/Unroll）的 taint 逻辑被报告为最多 2-3 个虚假的 cex，与 CellIFT 基线报告的 0 相差极小，端到端工作流未发现真泄漏。因此，在“相对精确 CellIFT 基线没有假阳性”的意义上，其精确性是有保证的。
- **显著降低面积与仿真开销（几何平均）**：
  - 插桩面积：Cell count 冗余从 5.64x（CellIFT-B）/4.99x（CellIFT-W）降至 1.42x（Frame）/1.31x（Unroll）；Gate count 冗余从 3.77x/1.80x 降至 1.04x/1.03x。
  - 仿真速度：相比 CellIFT-B/No-Refine 的 34.65x/67.17x 降速，Frame 方案仅为 1.79x，Unroll 方案为 1.60x。
- **Unroll vs. Frame 的权衡**：
  - Unroll 每个反例需要的精化点数较少（全局最优），但其整体最大可处理规模受限于解大规模 Max-SAT 的时间；在中型以上 BOOM 变体上超时。
  - Frame 在两核和全核范围内表现更好，多数情况下总延迟更低，并让精化后处理迭代可高度并发进行。通常需要的精化数量高于 Unroll 方案，但有时需要的迭代次数反而更少（由于在早期时间帧中清洗了虚假状态 DFF）。
- **属性驱动与自适应精化**：
  - 精化显著集中在对 MUX/选择逻辑的处理中：路径敏感逻辑（例如寄存器读取绕过链、控制/数据路径选择级联、地址数组读路径）过度作为 root 的 OR-of-taints 规则。
  - 精化在早期迅速推进，后期长尾效应不明显，说明快速仿真阶段可沿用固定精化逻辑结构稳定地工作。

### 7. 优点

- **全自动化流程**：无需人工判断“在哪里精化”和“如何精化”，克服了 Compass 需要启发式搜索和人工手册检查的局限，可便捷迁移至新设计和新属性。
- **方法理论严谨并具系统性**：
  - 用 NI 语义形式化 taint 精化，定义“精化格”候选集语义域；
  - 基于 Exchange（交换）性质进行批处理精化；
  - 提供完备的虚假性检查方法（参考精确 taint 仿真 + SAT self-composition）。
- **Where-refine 问题首次作为 Max-SAT 全局优化问题来处理**，能够在单个反例和单帧内得到最优/准最优精化集合，避免了局部贪心造成过度精化。
- **大面积降耗与精度双优**：比上代 bit 级 CellIFT 将面积和模拟开销减少超过 5-19 倍，同时达到极低假阳性（≤3 个虚假 cex），可直接部署到大规模验证中。
- **可扩展性和实用性**：Frame 方案可处理最大测试设计（Mega-BOOM），支持两种仿真器（Icarus 编译速度优先用于精化阶段、Verilator 吞吐优先用于大规模仿真），契合同一类模拟工作负载的形态。

### 8. 不足与局限

- **未处理“相关型（correlation-based）”不精确**：本文只精化每个模块自身的“局部结构不精确”（如对 value/taint 的联合值处理）；模块间共享输入产生的相关性假阳性（如一组 AND 门输出恒为常数却仍被 taint）没有列入精化范畴，有待未来工作解决。
- **词级粒度固有不精确**：对某个 word 只要有一位受秘密影响即整 word 标记 tainted，在打包字段（packed fields）、掩码、位切片等场景会引入额外的假阳性；这类词语级粗粒度问题未被彻底摈弃（是在权衡工程代价与优化空间之后接受的残留）。
- **全局最优不可扩展**：Unroll 算法在 Mega-BOOM 上超时；Frame 只在单帧上保证最优；因而两算法所得为“给定 cex/单帧”的最优精化，而非全局最小精化集合。
- **Frame 会过度精化**：它会对“被虚假 taint 但不影响 sink 的 DFF”进行清洗

- 这种“清洗所有帧内虚假状态”的策略并非严格最优：虽然它能更早阻断虚假 taint 的跨周期传播，但也可能将一些“不影响最终 sink”的中间状态一并精化，引入本可避免的逻辑冗余；当单帧内虚假状态较多且彼此无关时，Frame 的精化集合会明显大于 Unroll 的理论最小值。

- **实验场景的覆盖度有限**：论文只针对“安全指令集（SISP）”这一种源-汇属性进行验证，且激励由随机安全指令生成器产生；对于其他类型的信息流安全属性（如常数时间不变量、控制流完整性、多源多汇策略）以及更贴近真实攻击的恶意负载，普适性尚缺乏直接证据。

- **未处理时序猜测与瞬态执行类漏洞**：评测用例聚焦于“仅执行安全指令时不发生时间侧信道泄漏”，并未覆盖 Spectre、Meltdown 等由分支预测、乱序执行引起的瞬态信息流；因此 CEGAR-T 对这类漏洞的适用性仍是开放问题。

- **对设计前端与网表质量存在依赖**：框架基于 Yosys 解析后的门级网表，要求所有逻辑可综合、可展开；对于含模拟宏、锁存器、异步接口或未建模单元的设计，尚需额外工程适配。

- **缺少关键参数的敏感性分析**：例如 Max-SAT 规模与运行时间的关系、CEGAR-T 在不同指令长度/测试数量下的行为变化、精度与开销的 Pareto 前沿等，论文未给出系统的量化讨论。

- **对比基线的覆盖面有限**：仅与 CellIFT 家族及 No-Refine 对比，未涉及其他预硅安全验证工具（如商业信息流追踪工具或其他混合精确/抽象方法），其相对优势的定位仍需更多外部验证。

### 9. 总结与展望

CEGAR-T 的核心贡献在于将硬件信息流追踪中的“精化位置”与“精化程度”决策从人工经验或启发式规则转化为可求解的优化问题，并通过反例引导迭代逼近“零假阳性 + 最小开销”的平衡点。实验表明，在多种规模的 RISC-V 处理器上，它能在保持与精确 CellIFT 几乎一致验证精度的前提下，将面积冗余和仿真降速分别降低至接近 1 倍水平，显著提升了大规模预硅安全验证的可扩展性。与此同时，词级粒度引入的固有假阳性、相关型不精确、单帧最优的非全局性、以及实验场景的单一性，构成其现阶段的主要限制。

未来工作自然延伸的方向包括：将精化扩展到模块间共享输入引起的相关性假阳性；探索位级与词级混合粒度以兼顾精度与效率；将 CEGAR-T 适配到更多信息流安全属性（如多汇策略与瞬态执行模型）；以及在实际工业级验证流程中集成并验证其端到端收益。
