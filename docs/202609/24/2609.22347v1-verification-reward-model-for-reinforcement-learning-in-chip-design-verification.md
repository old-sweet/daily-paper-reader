## 摘要
我们提出了一个验证奖励模型（Verification Reward Model，VRM）框架，用于训练语言模型创建和修复芯片验证制品。其核心对象是一个版本化的验证契约，将需求、允许的激励、观测边界、参考行为、评估预算和验收标准绑定在一起。编译器、仿真器、形式化、变异、覆盖率和专家评审证据被转换为可审计记录。确定性验收检查仍位于学习模型之外。一个学习得到的结果模型根据规范、生成的制品以及显式掩码的部分证据，预测代价高昂的未来证据；一个语义评判器识别有证据支持的弱点；一个确定性奖励合成器将所得质量向量转换为任务条件化的训练奖励。扩展包括配对的无故障/故障干预、边际故障发现奖励、不确定性感知的评估调度，以及隔离的跨域学习循环。评估强调经独立验证的故障检测、误报、跨设计族的泛化能力，以及达到指定质量水平的总成本。我们描述了一个在小型、兼容开源工具的基准上使用轻量级模型的首个实验，其中完整 UVM 能力通过针对特定特性的资格认定予以纳入。本文是一篇立场论文：我们规定了该框架以及可用于检验它的实验，并且不报告任何训练、EDA 或硅片结果。

## Abstract
We propose a Verification Reward Model (VRM) framework for training language models to create and repair chip verification artifacts. The central object is a versioned verification contract that binds requirements, permissible stimulus, observation boundaries, reference behavior, evaluation budgets, and acceptance criteria. Compiler, simulator, formal, mutation, coverage, and expert-review evidence are converted into auditable records. Deterministic acceptance checks remain outside the learned model. A learned outcome model predicts expensive future evidence from the specification, the generated artifact, and explicitly masked partial evidence; a semantic critic identifies evidence-supported weaknesses; a deterministic reward composer translates the resulting quality vector into task-conditioned training rewards. Extensions include paired clean/fault interventions, marginal fault-discovery rewards, uncertainty-aware evaluation scheduling, and a quarantined cross-domain learning loop. Evaluation emphasizes independently validated fault detection, false alarms, generalization across design families, and total cost to reach a specified quality level. We describe a first experiment on a small, open-tool-compatible benchmark with lightweight models, with full UVM capability admitted through feature-specific qualification. This is a position paper: we specify the framework and the experiments that would test it, and we report no training, EDA, or silicon results.

## 1. 核心问题与整体含义

- **背景**：语言模型已能生成语法上合理的 SystemVerilog、断言与 testbench 组件，但要成为可靠的验证助手，需要奖励信号真正对齐验证工程师的关切——检测真实设计故障、对正确设计零误报、需求可追溯、评估成本有界。
- **核心问题**：简单代理指标无法提供该信号，且会被策略利用（reward hacking）：
  - 代码覆盖率可在检查能力削弱时反而上升；
  - 零失败断言可能从未被激活；
  - 无条件打印错误的 testbench 会“检测”所有故障和干净设计。
- **形式化定位**：奖励函数是映射 $(x, y, e) \mapsto R$，其中 $x$ 为验证问题、$y$ 为生成的验证制品、$e$ 为 EDA 工具证据。与对话偏好学习不同，该场景存在**可执行真值**（编译器、仿真器、形式化引擎、变异 campaign），但这些测量昂贵、部分且易被破坏。
- **真正的设计难题**：不仅是“奖励什么”，还包括**哪些量可以学习、哪些必须保持确定性、以及在完整 campaign 完成前如何使用部分证据**。
- **整体含义**：提出 VRM 框架，将验证质量视为**契约依赖、证据支撑**的量，把可信测量与学习预测严格分离，为芯片验证中的语言模型训练提供可审计的奖励路径。

## 2. 方法论

### 2.1 核心思想：三层分离

- **可信证据**（frozen contract + protected evaluator）→ **学习预测**（outcome model + semantic critic）→ **预算分配**（scheduler）。
- 实线路径将测量证据送入**确定性奖励合成器**；虚线路径仅支持选择与批评，**不替代契约要求的验收检查**。
- 学习组件绝不覆盖测量结果或验收判定。

### 2.2 验证契约（Verification Contract）

$$C = (S, D, I, O, A, G, B, V)$$

- $S$ 需求集、$D$ DUT 版本、$I$ 合法输入空间、$O$ 可观测性、$A$ 环境假设、$G$ 可信 oracle 与目标、$B$ 评估预算、$V$ 版本与来源。
- 策略只能编辑声明的制品路径，不能改动 DUT、参考模型、评分脚本、必需覆盖率 bin、变异种群、通过标准或工具约束。契约变更产生新任务版本。

### 2.3 五个服务

| 服务 | 角色 | 权限边界 |
|---|---|---|
| 可信评估器 $T$ | 执行版本化工具，产出证据 $e=T(C,y)$ | 拥有退出码、时限、trace 收集、受保护参考文件 |
| 结果模型 $O_\theta$ | 预测未来测量 | 仅用于排序与调度，绝不接收目标测量 |
| 语义评判器 $J_\phi$ | 结构化评估需求对齐、架构、潜在缺口 | 每条诊断须链接需求/代码位置/证据，未验证者标为假设 |
| 奖励合成器 $U$ | 固定有效性规则 + 版本化标量化 | 预测效用不能覆盖测量结果 |
| 评估调度器 $A_\psi$ | 选择下一候选/测试子集/保真度 | 无权更改验收标准 |

- **结果模型**：$p_\theta(q_{>k} \mid C, y, e_{\le k}, m_k)$，掩码 $m_k$ 标识实际观测内容；模型绝不能通过日志、文件名、摘要或元数据接收目标测量。标量效用头 $u_\theta$ 用于排序与调度。
- **为何需要学习模型**：其价值在于预测未运行的回归、解释局部代码/证据交互、在部分观测下排序候选、估计可修复性、决定哪项额外测量最有信息量。

### 2.4 证据表示与信任边界

- **证据记录**：契约摘要、候选摘要、工具链摘要、评估阶段、时间戳、工作负载/种子标识、测量单位、状态、不确定性、原始工件引用；**追加式**。
- **状态**：`pass` / `fail` / `unknown` / `not_run` / `infrastructure_error`。形式化超时通常为 `unknown`；worker 崩溃为 `infrastructure_error`；可复现的候选引发死锁在契约定义完成界限时可为任务失败。
- **结构化证据通道**：编译、仿真、覆盖率（原始分子/分母/排除项/层次/版本）、断言（尝试、非空激活、失败、reset-disable 区间、未决义务）、变异（验证状态、故障族、检测机制、复现器）、运行时（排队/编译/仿真/解析/推理分离）。
- **证据阶段**：E0（仅契约+制品）→ E1（lint+编译）→ E2（固定 smoke 套件）→ E3（更大干净回归+需求覆盖）→ E4（验证过的故障 campaign）→ E5（独立审计：隐藏故障族、替代干净实现、第二套合格工具流）。训练 E0→E4、E1→E4、E2→E4 的独立头或阶段条件模型。
- **仓库级上下文**：围绕接口、事务定义、候选 diff、需求、检查器调用点、依赖切片做**有界检索**，并记录哪些文件被省略；先特征+紧凑编码，再测试更丰富检索/图编码器。

### 2.5 故障检测作为合格目标

- **验证过的故障种群 $M_C$**：变异仅在满足“可构建、与合法操作条件相关、在这些条件下改变可观测需求”后才合格。等价、契约下不可达、无效、未解决的变异**分开分类**；超时不等于等价证明。
- **有效击杀定义**：$K(t,m)=1$ 仅在检测归因后成立。故障被计为检测需满足：在验证过的故障 DUT 上产生**可复现、契约相关**的失败，且在配对干净对照上表现可接受。缺失库或仿真器崩溃不算检测；无条件打印错误的候选因干净对照失败而失去资格。
- **召回与误报使用显式单位**：

$$P = \frac{TP}{TP+FP}, \qquad R = \frac{TP}{TP+FN}$$

  - 四个计数必须由同一 episode 定义支配；“唯一有缺陷设计数”与“数百万干净事务数”混合不能得到精确率。
  - 按故障族报告变异召回率，单独报告干净误报率。
  - 零观测干净失败**不建立**零误报概率：$n$ 次试验零失败的单侧 95% 上界为 $1-0.05^{1/n}$，$n=100$ 时约 **2.95%**；相关种子需聚类感知分析。

### 2.6 奖励设计

- **质量向量**：$q=(q_{\text{fault}}, q_{\text{req}}, q_{\text{robust}}, q_{\text{eff}})$，$q_j \in [0,1]$。故障质量为固定验证种群上的严重度加权检测；需求质量为独立插桩、已检查义务；鲁棒性为预定义合法压力场景；效率为同等质量下运行时的有界变换。原始代码覆盖率与主观风格仅作诊断。
- **起始标量化权重**：$(0.55, 0.25, 0.15, 0.05)$——明确为假设而非经验最优。
- **资格先于效用**：

$$R_{DV} = \begin{cases} -1, & \text{篡改或确认不可靠} \\ -0.5, & \text{可归因的构建/任务失败} \\ \text{NA}, & \text{所需证据未解决} \\ \sum_j w_j q_j, & \text{合格证据完整} \end{cases}$$

  - `NA` 意味着样本被掩码或留待另一次评估，**不静默转为 0**；控制器为未解决工作预留预算，防止故意耗尽资源获得免费通过。
  - 资格包括：受保护文件完整性、正确绑定、最小活动、干净对照行为、参考 oracle 有效性、所有任务必需证据。**全局惩罚每次仿真失败的规则不适用于验证生成**。
- **边际套件效用**：$F(S) = \frac{\sum_{m \in M_C} v_m \mathbf{1}[\exists t \in S: K(t,m)=1]}{\sum_{m \in M_C} v_m}$，新测试的增量为 $F(S \cup \{t\}) - F(S)$；重复检测已覆盖故障不再获得发现信用，分母在整个 campaign 中冻结。运行时成本可作为单独有界

成本项，例如 $F(S) - \lambda \cdot \text{cost}(S)$，使发现信用与仿真开销分离记账，避免用“多跑无害测试”刷分。

- **与 RLHF/偏好优化的区别**：本框架不把奖励建模为人类偏好代理，而是**可执行真值的分层测量**；偏好/批评仅用于诊断与调度，不进入验收。奖励合成器的标量化规则版本化并冻结，策略无法通过改变自身输出来改写打分函数。

### 2.7 反 reward hacking 与训练流程

- **主要攻击面与对策**：
  - *弱化检查*（删断言、放宽断言、缩短仿真、跳过 smoke）→ 契约固定必需覆盖率 bin、smoke 套件与变异种群，资格检查拒绝缺项制品；
  - *污染对照*（让干净设计也失败以“检测”所有故障）→ 干净对照行为纳入资格，误报直接使样本不合格；
  - *过拟合可见故障*→ 隐藏故障族用于 E5 审计，训练期不可见；
  - *资源耗尽换通过*→ `NA` 不被静默转 0，控制器为未解决项预留预算；
  - *证据伪造/篡改*→ 追加式证据记录 + 受保护参考文件完整性校验，篡改直接判 $R_{DV}=-1$；
  - *元数据泄露*（日志/文件名暗示目标测量）→ 结果模型输入显式掩码 $m_k$，禁止目标测量进入预测通道。
- **训练流程（设计意图）**：先以冻结契约跑 E0→E4 收集证据与奖励，训练结果模型与语义评判器；再用结果模型做候选排序与测试子集选择，由调度器在预算内决定下一项测量；仅当证据完整时合成最终奖励并回传策略。学习组件全程处于“建议”通道，验收始终由确定性合成器裁决。

## 3. 实验设计方案（作者声明无实测结果）

- **任务与基准**：以带版本化契约的验证生成任务为单位，覆盖语法/功能断言、testbench、形式化属性等制品类型；故障种群 $M_C$ 按故障族分层，干净对照与隐藏故障族分离。
- **对比基线（设计）**：至少应包括——原始代码覆盖率驱动的奖励、零失败断言驱动的奖励、纯 LLM 偏好/风格评分、无资格检查的朴素效用奖励，以及本文的分层测量奖励。目的是展示代理指标在对抗性策略下的失效模式，而非仅比较平均性能。
- **指标（设计）**：
  - 严重度加权的**变异召回率**（按故障族报告）；
  - **干净误报率**及其单侧置信上界（如 $n$ 次零失败的 $1-0.05^{1/n}$）；
  - 需求覆盖的独立插桩比例；
  - 效率（同等质量下的运行时/仿真预算）；
  - 资格与篡改检出率、`NA` 比例、基础设施错误率等过程指标。
- **消融（设计）**：
  - 去掉资格检查 → 预期出现“无条件报错”与弱化检查的刷分；
  - 去掉干净对照 → 预期误报率不可控；
  - 去掉隐藏故障族 → 预期对可见故障过拟合；
  - 替换结果模型为随机排序 → 检验调度增益；
  - 改变标量化权重 → 检验质量向量的稳健性。
- **证据阶段实验（设计）**：比较 E0/E1/E2 阶段条件模型预测 E4 结果的能力，检验“部分证据下排序”的可用性与信息增益。
- **审计协议（设计）**：E5 使用隐藏故障族、替代干净实现与第二套合格工具流，作为独立于训练管线的验收。

## 5. 局限与风险

- **契约依赖**：奖励可信度完全建立在契约质量上；契约定义不当（漏掉必需覆盖率 bin、故障种群不合格、oracle 有缺陷）会使整套测量失真，而框架本身不自动发现这类问题。
- **故障种群构造成本高**：变异需逐一验证“可构建、契约相关、改变可观测需求”，等价/不可达/无效变异的分类本身开销大，且“超时不等于等价”使判定困难。
- **统计效力有限**：干净误报的零观测只能给出较宽的置信上界，小样本下难以证明“接近零误报”；相关种子需聚类感知分析，增加评估复杂度。
- **学习模型的边界**：结果模型被限制为不接触目标测量，其预测能力受证据阶段与掩码约束；在 E0/E1 早期证据稀疏时，排序增益可能有限甚至误导。
- **权重与标量化的主观性**：质量向量权重与效率惩罚形式未经验证，可能引入隐含偏好；不同工艺/设计域的可迁移性未知。
- **无实证支撑**：全部主张均为设计论证，尚未证明在真实 EDA 流程与强化学习训练中可行、稳定或优于现有奖励设计。

## 6. 结论与启示

- **核心贡献**：提出将芯片验证中的奖励建模为**契约依赖、证据支撑、分层测量**的问题，通过“可信证据 → 学习预测 → 预算分配”三层分离，把可信测量与学习预测严格解耦，为语言模型在验证场景中的训练提供可审计路径。
- **关键设计原则**：
  1. 资格先于效用，测量结果不可被预测覆盖；
  2. 代理指标（覆盖率、零失败断言、风格）仅作诊断，不作验收；
  3. 误报与召回使用显式单位、按故障族报告，零观测不等于零风险；
  4. `NA` 不被静默转为 0，防止资源耗尽换通过；
  5. 隐藏故障族与独立审计作为反过拟合手段。
- **实践启示**：任何面向验证的 RL/奖励设计，应优先回答“哪些量必须保持确定性、哪些量可以学习、部分证据下如何排序与调度”，而非直接优化可被策略利用的代理指标；奖励函数本身需要版本化、冻结与可审计。
- **开放问题**：契约的形式化与自动检查、故障种群的高效构造与等价判定、部分证据下的统计校准、跨设计域权重迁移，以及端到端实证验证。
