## 摘要
IC3 是一种用于硬件模型检测的最先进算法，它通过增量构造由一组引理组成的归纳不变式来证明安全性质。其有效性取决于泛化启发式，这些启发式用于识别有用的引理并引导证明搜索。然而，许多领先的 IC3 硬件模型检测器工作在降阶的位级表示上，难以利用高层设计关系进行泛化。那些工作在更高层次上的检测器在利用高层设计结构和语义方面仍然受限。我们提出 Agentic-IC3，它构建在 Pono 的字级模型检测基础设施之上，将语言模型智能体集成到 IC3 中，以利用寄存器传输级（RTL）设计信息来引导语义证明搜索。该框架为持久化 IC3 后端提供面向智能体的接口，使智能体能够在整个验证过程中与显式且不断演化的证明状态交互。在相继的证明义务中，智能体将中间证明状态和求解器反馈与 RTL 相关联，并通过 SAT 和 UNSAT 泛化提出高层引理。除泛化外，智能体还可以引入派生观察信号以简洁地表达设计关系并获得更有信息量的反馈，并进行回溯以修正会导致无成效证明分支的提议。后端在更新证明状态之前检查提议，从而保持健全性并为进一步推理提供反馈。在涵盖安全信息流验证以及通信协议、处理器和功能单元的功能验证的 14 个基准套件上，Agentic-IC3 在一小时超时内求解了 10 个案例，其中包括三个被评估基线 rIC3、Pono-IC3Bits 和 A-IC3 均未求解的 4 个案例。

## Abstract
IC3 is a state-of-the-art algorithm for hardware model checking that proves safety properties by incrementally constructing an inductive invariant consisting of a set of lemmas. Its effectiveness depends on generalization heuristics that identify useful lemmas and guide proof search. However, many leading IC3 hardware model checkers operate on lowered, bit-level representations, where high-level design relationships are difficult to exploit for generalization. Those operating at a higher level remain limited in exploiting high-level design structure and semantics. We present Agentic-IC3, built on Pono's word-level model-checking infrastructure, which integrates a language-model agent into IC3 to guide semantic proof search using register-transfer-level (RTL) design information. The framework exposes an agent-oriented interface to a persistent IC3 backend, allowing the agent to interact with an explicit, evolving proof state throughout verification. Across successive proof obligations, the agent relates intermediate proof states and solver feedback to the RTL and proposes high-level lemmas through both SAT and UNSAT generalization. Beyond generalization, the agent can introduce derived observation signals to express design relationships succinctly and obtain more informative feedback, and backtrack to revise proposals that lead to unproductive proof branches. The backend checks proposals before updating the proof state, preserving soundness and providing feedback for further reasoning. On a suite of 14 benchmarks spanning security information-flow verification and functional verification of communication protocols, processors, and functional units, Agentic-IC3 solves 10 cases within a one-hour timeout, including 4 unsolved by all three evaluated baselines: rIC3, Pono-IC3Bits, and A-IC3.

## 1. 核心问题与整体含义（研究动机与背景）

- **背景**：IC3/PDR 是硬件模型检测中最先进的算法之一，通过增量构造由一组**引理（lemma）**组成的归纳不变式来证明安全性质。其框架维护帧序列 $F_0,\dots,F_k$（$F_i$ 是对 $i$ 步内可达状态的过近似，$F_0=\text{Init}$），并满足 $F_i \Rightarrow F_{i+1}$、$F_i \wedge T \Rightarrow F'_{i+1}$；当相邻帧等价时即得到归纳不变式。
- **核心痛点**：IC3 的效力高度依赖**泛化（generalization）启发式**——即如何把具体状态/证明义务扩展为覆盖更广状态的有用引理。
  - **位级 IC3**（如 rIC3、Pono-IC3Bits）工作在降阶的布尔表示上，可通过文字删除等方式高效泛化，但**高层设计关系在降阶后难以识别**，表达一个高层关系往往需要多条位级子句（例如字级等式 $u=v$ 需 $2n$ 条子句）。
  - **字级 IC3** 保留多比特运算，引理表达力更强（可直接写等式、算术约束），但**搜索空间更大**，启发式容易错过有用候选，且开发有效泛化策略需要大量专家工作。
- **已有路线**：基于启发式/综合文法/抽象规则的方法、扩展证明词汇、利用应用特定结构，以及 ML 路线（NeuroPDR、DeepIC3、A-IC3）和 LLM 路线（Large Lemma Miners、CIll、IC3Syn）。这些方法的泛化规则与候选表示往往与特定设计/性质绑定，**指导能力难以跨应用迁移**。
- **论文主张**：应让语言模型在 IC3 中承担更广的角色——不仅生成引理，还能利用证明搜索过程中累积的证据来**提议引理并修正决定后续证明义务的决策**，且整个交互保持在 RTL 语义层。

## 2. 方法论

### 2.1 核心思想
- 基于 **Pono 的字级模型检测基础设施**，把语言模型智能体作为 **IC3 的证明搜索策略（proof-search policy）** 接入。
- 采用**持久化 IC3 后端 + 面向智能体的接口**：证明内核（搜索控制器、演化的证明状态、SAT/SMT 校验）在泛化步骤向智能体发出 `RequestGeneralization` 请求，智能体从三种动作中选择一种回应：
  - **PROPOSE**：SAT / UNSAT 泛化，提出引理；
  - **OBSERVE**：引入派生观察表达式；
  - **BACKTRACK**：回到更早的证明义务修正先前提议。
- **健全性由后端保证**：智能体的任何提议都必须通过 SAT/SMT 检查（初始性、相对归纳性、BMC 可达性检查）才会更新证明状态，失败则以反例形式反馈给智能体继续推理。

### 2.2 关键技术细节

**（a）RTL 证明表示与接口**
- 智能体读取 RTL、性质、假设，并获得当前状态变量及其位宽；证明义务、帧引理、求解器反馈均以 **RTL 信号名与表达式**呈现。
- 引理用 **Verilog 表达式子集**（算术、比较、位运算、拼接）书写，经前端解析与类型检查后编译为**无量词位向量（QF_BV）SMT 公式**。
- **持久证明会话**：帧、已接纳引理、证明义务、已注册观察在整个验证过程中保持可用；由长驻 CLI 进程保留求解器上下文，通过 JSON Lines 交换请求/响应。每个请求给出义务及其帧层 $i$、$F_{i-1}$ 的活跃引理，以及一批前驱区域或已检查的阻塞引理。

**（b）批量泛化（Batch Generalization）**
- 动机：若每次只给智能体一个前驱状态，容易提出只贴合该具体寄存器取值的引理，而看不出设计关系；因此仿照 IC3Syn，在 SAT 与 UNSAT 两处都提供批量样本（最大批大小 $b$，单次提议最多 $m_{\max}$ 条引理）。

- **SAT 批量泛化（Algorithm 1）**：
  1. 收集至多 $b$ 个满足 $F_{i-1}\wedge T\wedge q'$ 的前驱 $p$，各用常规 SAT 泛化扩成区域 $G$，并用 $E \leftarrow E \wedge \neg G$ 排除已覆盖区域；
  2. 向智能体请求提议 $(\ell_1,\dots,\ell_m)$，令 $L=\bigwedge_j \ell_j$；
  3. 后端检验 $F_{i-1}\wedge T\wedge q'\wedge \neg L$：若 UNSAT，说明没有任何前驱被排除，返回要求修正；
  4. 与传统 SAT 泛化要求"泛化区域内每个状态都一步到达 $q$"不同，本框架**放宽**该要求，允许 $\neg\ell_j$ 也包含不直接到达 $q$ 的状态，从而利用 RTL 关系排除更多不可达状态；
  5. 由于提议可能过强而排除可达状态，先用 **BMC 检查**深度 $i-1$ 内是否可达违反 $\ell_j$；若发现违例则作为反馈返回，否则递归阻塞 $(\neg\ell_j, i-1)$，再重发前驱查询。

- **UNSAT 批量泛化（Algorithm 2）**：先把已检查的阻塞引理积累成批 $B$（达到 $b$ 条或搜索需要时触发）；智能体提出 $\ell$ 可**替代**批中引理 $B_j$（条件为 $\ell \Rightarrow B_j$，即 $\neg\ell \supseteq \neg B_j$）；后端检查 $\text{Init}\Rightarrow\ell$ 与 $F_{i-1}\wedge\ell\wedge T\Rightarrow\ell'$，通过则把 $\ell$ 加入 $F_1,\dots,F_i$ 并移除被蕴含的批引理，否则返回失败检查的反例。

**（c）派生观察词汇（Derived Observation Vocabulary）**
- 允许智能体注册命名观察表达式（如 `obs.total = cnt1 + cnt2`、`obs.occupancy = rb.head - rb.tail`），其取值被加入后续证明请求与反例状态中，使**跨状态的组合关系直接可见**。
- 后端检查表达式并注册其名称、定义与位宽，然后带观察值再次询问智能体；观察在整个会话中持续可用，可跨证明义务复用并简化引理书写。

**（d）回溯与证明修正（Backtracking）**
- 动机：IC3 的局部查询只涉及单步转移，反馈仅描述当前步骤，智能体难以预判证明 $\ell$ 所需的递归义务；随着搜索推进，智能体可能意识到先前提议只是局部事实或方向不佳。
- 机制：当递归阻塞 $(\neg\ell, i-1)$ 时智能体可返回 `Backtrack`，**终止对该 $\ell$ 的递归尝试**，跳过同一响应中剩余引理，把控制权交回 $(q,i)$ 的泛化步骤；后端用保留的帧引理重发 $F_{i-1}\wedge T\wedge q'$ 查询。已接纳引理仍留在其已验证帧中，可继续剪枝后续搜索。

**（e）动机示例（图 2）**：双副本控制器信息流验证中，位级贪心泛化得到局部引理 $\ell_{\text{local}}\equiv(s_1[0]=0)$（只排除帧 1 的 DONE），而智能体依据 RTL 与输入假设提出 $\ell_{\text{sync}}\equiv(s_1=s_2)$，捕获跨执行阶段的关系，直接贡献于证明完成时序相同的归纳不变式。

## 3. 实验设计

- **基准（14 个）**，覆盖安全信息流验证与功能验证：

  - 来自 **Large Lemma Miners** 困难集的 FIFO、arithmetic-loop、仲裁（arbitration）基准；

  - 来自 Lu 等 ILA 模型的 **BSG 通信协议**缓冲溢出检查。
  - 选择原则：以对传统 IC3 引擎困难的用例为主，保留少量简单用例以评估智能体引导的额外开销。
- **对比基线（3 个）**：
  - **Pono-IC3Bits**：同一模型检测基础设施上的常规 IC3 基线；
  - **rIC3**：当前最先进的位级 IC3；
  - **A-IC3**：自适应选择泛化策略的 ML 辅助基线。
- **运行设置**：每个基准 1 小时超时；每次运行从全新的智能体对话与持久 IC3 会话开始；所有基准使用同一任务提示与接口文档；智能体对 RTL/文档/证明历史只有只读权限，仅有临时文件写权限；通过 shell 与内核交互，后端源码与内部状态文件在沙箱外；**禁用 shell 网络访问与网络搜索**。

- **消融实验**：在完整系统解出的 10 个基准上，分别关闭批量泛化、观察、回溯三种机制。
