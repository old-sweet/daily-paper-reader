## 摘要
我们提出了一种验证奖励模型（Verification Reward Model, VRM）框架，用于训练语言模型创建和修复芯片验证工件。其核心对象是一个带版本的验证契约，它将需求、允许的激励、观测边界、参考行为、评估预算和验收标准绑定在一起。编译器、模拟器、形式化、变异、覆盖率以及专家评审证据被转换为可审计记录。确定性验收检查仍保留在学习模型之外。一个学习得到的结果模型根据规范、生成的工件以及被显式掩蔽的部分证据，预测代价高昂的未来证据；一个语义评判器识别由证据支持的薄弱之处；一个确定性奖励合成器将所得质量向量转换为任务条件化的训练奖励。扩展包括成对的干净/故障干预、边际故障发现奖励、不确定性感知的评估调度，以及隔离的跨域学习循环。评估强调独立验证的故障检测、误报、跨设计族的泛化，以及达到指定质量水平的总成本。我们描述了一个在小型、兼容开放工具的基准上使用轻量级模型的首个实验，其中完整的 UVM 能力通过针对特定特性的资格认定而获准。这是一篇立场论文：我们阐述了该框架以及可用于检验它的实验，并且不报告任何训练、EDA 或硅片结果。

## Abstract
We propose a Verification Reward Model (VRM) framework for training language models to create and repair chip verification artifacts. The central object is a versioned verification contract that binds requirements, permissible stimulus, observation boundaries, reference behavior, evaluation budgets, and acceptance criteria. Compiler, simulator, formal, mutation, coverage, and expert-review evidence are converted into auditable records. Deterministic acceptance checks remain outside the learned model. A learned outcome model predicts expensive future evidence from the specification, the generated artifact, and explicitly masked partial evidence; a semantic critic identifies evidence-supported weaknesses; a deterministic reward composer translates the resulting quality vector into task-conditioned training rewards. Extensions include paired clean/fault interventions, marginal fault-discovery rewards, uncertainty-aware evaluation scheduling, and a quarantined cross-domain learning loop. Evaluation emphasizes independently validated fault detection, false alarms, generalization across design families, and total cost to reach a specified quality level. We describe a first experiment on a small, open-tool-compatible benchmark with lightweight models, with full UVM capability admitted through feature-specific qualification. This is a position paper: we specify the framework and the experiments that would test it, and we report no training, EDA, or silicon results.

## 2. 方法论：核心思想与关键技术细节

### 2.1 核心思想：可信证据、学习预测、预算分配分离

- **验证契约**：任务契约定义为  
  \( C = (S, D, I, O, A, G, B, V) \)  
  其中 \(S\) 是需求集，\(D\) 是 DUT 版本，\(I\) 是合法输入空间，\(O\) 定义可观测性，\(A\) 是环境假设，\(G\) 是可信 oracle 与目标，\(B\) 是评估预算，\(V\) 记录版本与来源。
- 策略只能编辑声明的 artifact 路径，不能改 DUT、参考模型、评分脚本、必需覆盖 bin、突变群、通过标准或工具约束，除非任务明确涉及且提供独立评估器。契约变更产生新任务版本。

### 2.2 五类服务

- **可信评估器 \(T\)**：执行版本化工具，产生证据 \( e = T(C, y) \)，拥有进程退出码、时间限制、trace 收集和受保护参考文件。
- **结果模型 \(O_\theta\)**：预测未来测量  
  \( p_\theta(q_{>k} \mid C, y, e_{\le k}, m_k) \)  
  其中 mask \(m_k\) 标识已实际观测内容。模型不能通过日志、文件名、摘要或元数据接收目标测量。其标量 utility head \(u_\theta\) 用于排序和调度。
- **语义 critic \(J_\phi\)**：结构化评估需求对齐、artifact 架构和可能缺口。每条断言链接到需求、代码位置或证据记录；未验证诊断标为假设。
- **奖励合成器 \(U\)**：应用固定有效性规则和版本化标量化，将测量结果映射为奖励。预测 utility 不能覆盖测量结果。
- **评估调度器 \(A_\psi\)**：选择下一个候选、测试子集或保真度，目标是证据获取和决策质量，无权改变验收标准。

### 2.3 证据表示与信任边界

- 证据记录包含：契约摘要、候选摘要、工具链摘要、评估阶段、时间戳、工作负载/seed 标识、测量单位、状态、不确定性、原始 artifact 引用。记录 append-only，候选控制的文本视为数据。
- 状态包括：`pass`、`fail`、`unknown`、`not_run`、`infrastructure_error`。
- 结构化证据通道：编译、仿真、覆盖率、断言、变异、运行时。强调必须能看见“零失败断言可能未激活”“零失配 scoreboard 可能比较了零事务”“覆盖率可能因分母变弱而上升”。
- 证据阶段：E0 仅契约和 artifact；E1 加 lint/编译；E2 加固定 smoke suite；E3 加更大 clean regression 和需求覆盖；E4 加验证过的故障 campaign；E5 加独立管理的隐藏故障族、替代 clean 实现或第二套合格工具流。

### 2.4 故障检测作为合格目标

- **验证过的故障群 \(M_C\)**：突变只有在能构建、与合法操作条件相关、并改变可观测需求后才 eligible。等价、契约下不可达、无效、未解决突变分开处理。
- **Sound kill 定义**：候选验证 artifact 在验证过的故障 DUT 上产生可复现、契约相关失败，且在配对 clean control 上表现可接受，才算检测。缺失库或模拟器崩溃不算有效检测。无条件报错候选会因 clean control 失败而失去资格。
- 对测试 \(t\) 和故障 \(m\)，\(K(t,m)=1\) 仅在检测归因后成立。重复表现同一根故障不变成多次发现。
- **召回与误报的显式单位**：在独立裁定的 design/workload episodes 上定义正例，精确率和召回率使用同一 episode 定义。不能把“唯一 buggy 设计数”和“百万 clean 事务数”混在一起算 precision。零 clean failure 不证明零误报概率；独立 Bernoulli 模型下，n 次零失败的 95% 单侧上界为 \(1-0.05^{1/n}\)，n=100 约 2.95%。

### 2.5 奖励设计
