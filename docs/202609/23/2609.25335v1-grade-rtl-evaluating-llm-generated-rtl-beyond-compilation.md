## 摘要
大型语言模型（LLM）能够根据自然语言规范生成寄存器传输级（RTL）代码，但仅凭编译无法确立结构完整性、功能正确性或实现效率。本文提出了一个超越编译来评估LLM生成RTL的框架，我们将其命名为GRADE-RTL。使用固定的提示词和验证设置，GRADE-RTL应用五项检查，例如端口签名、编译、精化、模块完整性，以及针对可信参考RTL的功能等价性。借助紧凑指标，我们识别候选设计在何处失败，并将端到端成功与具备下游综合资格区分开来。我们在三次生成尝试并带有失败导向反馈的预算下，对九个通用和RTL专用LLM在十个与边缘相关的知识产权设计上进行了评估。端到端成功率在评估模型中从0%到70%不等，失败不仅限于编译，还延伸到层次结构解析、逻辑不完整和行为不匹配。FPGA实现和65 nm ASIC综合结果进一步表明，功能等价的RTL在资源使用、时序、面积和功耗上可能差异很大。一个PID控制器布局布线案例研究说明了不同RTL实现的物理设计后果。GRADE-RTL通过将结构有效性、行为正确性和实现质量分开，为比较LLM生成的硬件描述提供了实用基础。

## Abstract
Large language models (LLMs) can generate register-transfer-level (RTL) code from natural-language specifications, but compilation alone does not establish structural completeness, functional correctness, or implementation efficiency. This paper presents a framework for evaluating LLM-generated RTL beyond compilation, which we named GRADE-RTL. Using fixed prompts and validation settings, GRADE-RTL applies five checks, such as Port Signature, Compilation, Elaboration, Module Completeness, and Functional Equivalence against trusted reference RTL. With the help of compact metrics, we identify where candidates fail and distinguish end-to-end success from eligibility for downstream synthesis. We evaluate nine general-purpose and RTL-specialized LLMs on ten edge-relevant intellectual property designs under a budget of three generation attempts with failure-directed feedback. End-to-end success ranges from 0% to 70% across the evaluated models, with failures extending beyond compilation to hierarchy resolution, incomplete logic, and behavioral mismatch. FPGA implementation and 65 nm ASIC synthesis results further show that functionally equivalent RTL can differ substantially in resource use, timing, area, and power. A PID-controller place-and-route case study illustrates the physical-design consequences of different RTL implementations. GRADE-RTL provides a practical basis for comparing LLM-generated hardware descriptions by separating structural validity, behavioral correctness, and implementation quality.

## 1. 核心问题与研究动机

- **背景**：边缘系统（EDGE Systems）将控制、通信、安全、存储与嵌入式计算 IP 集成在严格的面积、功耗、时序约束下，设计复杂度持续上升，催生对自动化设计方法的需求。LLM 正成为能将自然语言规范翻译为 RTL 代码的"设计期助手"。
- **核心问题**：**编译通过 ≠ 设计合格**。编译成功无法揭示模块层次断裂、参数缺失、逻辑不完整、子模块缺失等结构性问题；即便通过编译与功能验证，不同 RTL 描述在 FPGA/ASIC 实现后仍可能呈现显著不同的时序、面积与功耗。
- **整体含义**：RTL 生成质量的评估必须从"是否编译/是否功能正确"扩展到 **前端验证（接口 + 功能）+ 后端实现证据（FPGA/ASIC QoR）** 的多维度评估。
- **定位**：作者明确将 GRADE-RTL 定位为**互补性框架**而非首个统一评估方法。最接近的工作是 TuRTLe（集成多基准、评估语法/功能/可综合性/PPA/行补全），但因基准套件、模型集、协议与后端流程不同，**不做直接数值比较**。
- **相较前人工作的四点差异**：
  1. 使用来自 OpenCores 的可信参考 RTL，评估**真实 IP 级设计**（而非小型教学电路）；
  2. **显式分离模块完整性（MC）与功能等价（FE）**，区分"未完成实现"与"行为不匹配"；
  3. 对所有开源/闭源模型采用**固定的失败导向精化预算**，保证公平可复现；
  4. 将前端验证与 FPGA + 65 nm ASIC 实现证据（含 Innovus 布局布线案例）相连接。

## 2. 方法论

### 2.1 核心思想
将 LLM 视为黑盒 RTL 生成器，在**固定提示词、固定工具版本、固定验证脚本与实现约束**下，对生成结果执行五阶段前端验证；对失败设计施加**有界、阶段特定的诊断反馈**进行精化；对通过前端验证的候选执行 FPGA/ASIC 实现以量化 PPA。最终用紧凑指标分离"结构有效性、行为正确性、实现质量"。

### 2.2 五阶段前端验证流程
1. **端口签名（PPS, Port Signature）**：校验模块接口（头文件 / I/O）。
2. **编译（CR, Compilation）**：检查 Verilog-2001 语法与合法性。
3. **精化（ER, Elaboration）**：解析层次结构、参数与绑定关系。
4. **模块完整性（MC, Module Completeness）**：识别占位符（stub）、未驱动输出、不完整逻辑。
5. **功能等价（FE, Functional Equivalence）**：基于 **Yosys 的等价性检查流程**，与可信参考 RTL 比对；无法建立等价、报错或超时均判为 FE 失败。

### 2.3 错误处理与精化机制
- 失败时，从**最早失败的阶段**生成简洁诊断消息（如语法问题、参数不匹配、复位错误、缺失模块）。
- 模型**无法访问**验证工具、日志或实现报告，仅接收自然语言诊断。
- 所有模型统一使用 **K = 3** 的固定精化预算，确保改进源自对验证反馈的有效利用，而非无限制的提示迭代。

### 2.4 评估指标（文字化公式）
设 N 为基准设计数，y_i^(a) 表示设计 i 在第 a 次尝试中是否通过全部五个验证阶段（1/0）：

- **E2E@1**：首次尝试即端到端成功的比例，即对 N 个设计求 y_i^(1) 的平均值。
- **E2E@K**：在 K 次预算内至少有一次成功的比例，即对每个设计取 max(1≤a≤K) y_i^(a) 后再求平均。**E2E@K 与 E2E@1 的差值量化了验证引导精化的收益**。
- **SEY@K（Synthesis-Eligible Yield）**：在精化预算内**通过 CR 与 ER** 的设计比例，反映"可进入综合的生存能力"而非正确性。E2E@K 与 SEY@K 之间的差距，标示出"能进综合但不完整或功能错误"的设计。
- **首次失败分布（First-Failure Breakdown）**：将失败归类为接口/编译器失败、不可精化失败、部分模块失败、功能不匹配失败。
- **阶段级成功率与条件产出率（stage-wise rates / conditional yields）**：定位 PPS→CR→ER→MC→FE 各环节的失败位置。

### 2.5 实现级评估
- 仅 **同时通过 MC 与 FE** 的候选进入 FPGA 与 65 nm ASIC 流程做 PPA 评估；仅满足综合资格的候选保留在生存率统计中，但**不被视为正确实现**。

## 6. 主要结论与发现

- **端到端成功率区间为 0%–70%**（跨评估模型），失败不限于编译阶段，广泛延伸到**层次解析、逻辑不完整与行为不匹配**。
- **早期合法性不保证完整 RTL**：多个模型通过 PPS 与 CR，却在 ER 或 MC 阶段损失候选；Fig. 5 显示最大区分度出现在**编译之后，尤其是 ER 与 MC 阶段**——语法有效并不意味着层次一致或逻辑完整。
- **难度是设计特定的，而非仅由类别决定**：AES-128、SHA-256、Toom-Cook 是最少被解决的設計；Present Cipher 与 Schoolbook 被多个模型解决。
- **功能等价 RTL 的实现质量差异显著**：
  - FPGA 侧：控制与通信模块（UART、Wishbone RAM）接近参考；Schoolbook 乘法器差异最大（Gemini、OriGen 的 FF 用量远高于基线，Claude 资源接近但时序不同）；Present Cipher 呈现模型相关的资源/功耗权衡。
  - ASIC 侧：控制类设计相对稳定（UART 候选单元数少于基线且保持正裕量）；算术类波动大——Schoolbook 上 Gemini 紧凑、OriGen 面积与总功耗升高、Claude 功能正确但贴近时序边界（裕量仅 0.41 ns）；PID 上 RTLCoder 紧凑（899 cells / 0.138 mW），Claude 显著膨胀（6,794 cells / 1.284 mW），而两者裕量相近。
- **PID 案例**：布局布线后参考实现 1,902 个单元，Claude 实现 6,794 个单元（5,190 组合 + 739 时序），时序单元占比从 20.5% 降至 10.9%，物理面积更大——**功能等价不是实现质量指标**。
- **总体论断**：编译不确立功能正确，功能正确不确立实现质量；评估应区分结构有效性、行为正确性与实现效率，而非坍缩为单一通过率。未来 RTL 生成器应获得**硬件感知反馈**，而不仅是编译器或等价性诊断。

## 7. 优点

- **评估维度解耦设计清晰**：PPS / CR / ER / MC / FE 五阶段串联，并把 MC 与 FE 显式分离，能区分"未完成的实现"与"行为不匹配"，诊断粒度优于仅报告编译率或功能通过率的工作。
- **指标设计有洞见**：E2E@1 与 E2E@K 的差值量化精化收益；SEY@K 独立刻画"可综合生存力"，其与 E2E@K 的差距直接暴露"能进综合但错误"的隐患，避免了把可综合性等同于正确性的常见误区。
- **公平性与可复现性**：统一提示结构、统一 K=3 有界预算、统一工具与约束，并承诺公开提示词、脚本、日志、模型配置与评估产物。
- **覆盖真实 IP 级设计**：使用 OpenCores 多模块 IP 与可信参考 RTL，比小型教学电路更贴近边缘硬件实际；基准强调架构多样性。
- **前后端贯通**：把前端等价性与 FPGA（Artix-7）+ 65 nm ASIC（Genus）+ Innovus 布局布线证据串联，用统一的 65 nm/PVT 环境隔离 RTL 组织差异，提供了功能正确性之外的实现视角。
- **对自身定位克制**：明确与 TuRTLe 互补而非竞争，不宣称首个统一方法，学术态度审慎。
- **开源/闭源模型同台评估**：在相同有界交互预算下比较，兼顾了生态多样性。

## 8. 不足与局限

- **训练数据污染风险**：基准使用公开 IP 以便做参考等价性检查，**无法排除与模型训练数据的重叠**，可能高估部分模型的实际生成能力。
- **精化预算的局限**：K=3 衡量的是**有界生成鲁棒性**，而非无限制的智能体式修复能力，因此不能外推为模型的修复上限。
- **ASIC 证据不完整**：仅提供综合级 QoR 与**一个**布局布线示例，**不构成完整 sign-off 或硅验证**；作者明确将其定位为逻辑综合级证据而非物理签核。
- **单轨迹、无统计推断**：每个 model–design 配对只有一条受控生成轨迹，缺少重复采样、方差与置信区间，无法刻画模型输出的随机分布。
- **实验覆盖有限**：仅 10 个设计、9 个模型；无消融实验（K 值、提示模板、反馈形式、阶段定义均未做敏感性分析）；未覆盖定制/未见规范、更大规模层次化子系统与跨工具复现。
- **跨研究可比性受限**：与 TuRTLe 等因基准套件、模型集、协议与后端流程差异**无法进行有意义数值比较**，削弱了结论的外部参照。
- **算力信息缺失**：未报告 GPU/推理资源与运行时长，复现者难以评估成本，也限制了结果的可扩展性判断。
- **工程约束的简化**：FPGA 仅用单一器件（Artix-7）与 100 MHz 目标，ASIC 仅用单一 65 nm 库与 TT/1.0 V/125 °C 角，结论对工艺、频率与约束变化的稳健性未知。
