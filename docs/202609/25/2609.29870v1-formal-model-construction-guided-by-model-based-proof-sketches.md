## 摘要
形式化建模为系统正确性提供了强有力的保证，但开发和修复形式化模型仍然劳动密集，并且需要逻辑和形式推理方面的大量专业知识。近期基于大语言模型（LLM）的自动形式化智能体试图通过生成候选形式化模型，并利用形式化工具的反馈对其进行修正，来减轻这一负担。然而，现有方法遵循“生成—修复”范式，其中修复由所生成模型的验证失败驱动，因此严重依赖于反馈的粒度以及LLM的修复能力。因此，针对某一验证层级的修复可能会使另一层级的性质失效，这要求对完整的事件守卫集合进行推理。为解决这些局限，我们提出证明草图引导的形式化模型合成（Proof-Sketch-Guided Formal Model Synthesis，ProGS），一种以基于模型的证明草图为核心的自动形式化方法。基于模型的证明草图将目标形式系统的证明结构表示为一棵树。内部节点刻画情形拆分和归纳推理步骤，而叶节点对应于实现各个子目标的具体状态转移事件。ProGS 使用LLM生成和修复这些草图，并将验证失败映射回特定节点和子树，从而为迭代修复提供结构化指导。我们在一个包含27个形式系统的基准上的评估表明，ProGS 在语法有效性、演绎可验证性和行为正确性方面优于最先进的智能体式形式化建模方法，证明了围绕分层证明草图组织形式化模型构建的益处。

## Abstract
Formal modeling provides strong guarantees about system correctness, but developing and repairing formal models remains labor-intensive and requires substantial expertise in logic and formal reasoning. Recent LLM-based autoformalization agents seek to reduce this burden by generating candidate formal models and revising them using feedback from formal tools. However, the existing approaches follow a generate-and-repair paradigm, in which repairs are driven by verification failures of the generated model and therefore depend heavily on both the granularity of the feedback and the LLM's repair capability. As a consequence, a repair targeting one level of verification may invalidate properties at another level, which requires reasoning over the complete set of event guards. To address these limitations, we propose Proof-Sketch-Guided Formal Model Synthesis (ProGS), an autoformalization method centered on model-based proof sketches. A model-based proof sketch represents the proof structure of the target formal system as a tree. Internal nodes capture case splits and inductive reasoning steps, while leaf nodes correspond to concrete state-transition events that realize individual subgoals. ProGS uses LLMs to generate and repair these sketches, with verification failures mapped back to specific nodes and subtrees to provide structured guidance for iterative repair. Our evaluation on a benchmark of 27 formal systems shows that ProGS improves over state-of-the-art agentic formal modeling approaches in syntactic validity, deductive verifiability, and behavioral correctness, demonstrating the benefit of organizing formal model construction around hierarchical proof sketches.

- **背景**：形式化建模（如 Event-B）能为并发协议、安全攸关软件、分布式系统等提供严格的正确性保证，但构建正确的形式化模型高度劳动密集，需要逻辑、规约语言与形式推理方面的深厚专业知识。模型验证失败后还需反复诊断与修复。
- **现有方法的局限**：近期基于 LLM 的自动形式化智能体采用"生成—修复"（generate-and-repair）范式，依赖模型检查器或定理证明器的反馈来修复候选模型。但该方法存在两个关键问题：
  - **反馈粒度不匹配**：模型级反馈（如死锁轨迹）只能暴露全局性质违例，难以定位具体故障组件；组件级反馈（如单个事件的不变式保持证明义务）虽能定位到事件，但模型被表示为"扁平组件集合"，孤立修复单个事件会忽略事件间的隐藏依赖。
  - **修复顾此失彼**：针对某一验证层级的修复可能使另一层级的性质失效，尤其死锁自由性因涉及所有事件守卫的析取，无法像不变式保持那样被分解为局部证明义务，定位信息有限。
- **核心挑战**：系统级形式化建模的关键不只是生成/修复单个组件，而是**组织组件间的依赖关系**，使局部修复与全局验证需求保持一致。
- **整体含义**：论文提出以"基于模型的证明草图"（model-based proof sketch）作为中间表示，将形式模型构建组织为分层证明结构，实现更精准的故障定位与更协调的修复，为 LLM 驱动的形式建模提供新范式。

## 2. 方法论：核心思想与关键技术细节

### 2.1 核心思想

- 提出 **ProGS（Proof-Sketch-Guided Formal Model Synthesis）**，以树形证明草图为中间表示，连接目标系统的分层证明结构与实现其行为的状态转移事件。
- 证明草图 $\mathcal{P} = (\mathcal{N}, \mathcal{E})$ 为一棵树：
  - **内部节点** $n_i = (grd, \{\})$：只含守卫，表示中间证明条件或情形拆分条件；
  - **叶节点** $n_l = (grd, act)$：含守卫与动作，对应具体状态转移事件；
  - **边** $(n_p, n_c)$：父子关系，表示条件的细化/特化。
- 通过分而治之，将系统级推理分解为节点级、更简单的证明义务，降低验证难度；验证失败可映射回具体节点与子树，提供结构化修复指导。

### 2.2 整体流程

1. **环境模型构建**：LLM 根据自然语言需求文档生成环境模型 $\Gamma$（常量、集合、公理、变量、不变式、变体），迭代修复编译与类型错误直至良构。
2. **不变式依赖识别与验证**：LLM 识别不变式/变体之间的四类依赖，并用证明义务验证：
   - **等价**：$P \Leftrightarrow Q$
   - **蕴含**：$P \Rightarrow Q \wedge \neg(Q \Rightarrow P)$
   - **情形拆分**：$P \Leftrightarrow \bigwedge_{i=1}^{n} Case_i$
   - **归纳**：检查 $\neg(P \Rightarrow Q) \wedge \neg(var=0 \Rightarrow Q) \wedge (P \wedge var=0 \Rightarrow Q)$
3. **生成初始证明草图**：基于需求、环境模型与依赖关系，由 LLM 生成初始草图。
4. **草图清洗（确定性归一化）**：
   - 移除无动作的伪叶节点（除非显式表示终止/观测/跳过事件）；
   - 合并一元分支（将单子节点的子节点合并入父节点，守卫合并）；
   - 提取公共守卫（为共享守卫的兄弟节点引入抽象父节点）。
5. **结构检查**：
   - **死锁自由性**（公式 3）：对每个内部节点 $n_i$，其守卫须蕴含其所有子节点守卫的析取：
     $$\Gamma \vdash \bigwedge_{n_i \in \mathcal{N}} \left( n_i.grd \Rightarrow \bigvee_{n_c | (n_i,n_c) \in \mathcal{E}} n_c.grd \right)$$
     保证每个情形拆分被至少一个子分支覆盖，防止引入意外死锁。
   - **父子守卫有效性**（公式 4）：每条边 $(n_p, n_c)$ 满足 $n_c.grd \Rightarrow n_p.grd$，保证子分支是父条件的有效细化。二者结合确保子分支恰好覆盖父节点行为，使不变式保持可从叶节点向上传播至根节点。
6. **结构代价评分与最佳-of-n 选择**：
   $$s\_cost = \frac{1}{3} \times \left( \frac{|structural\_check\_fails|}{|\mathcal{N}|} + \frac{1}{depth} + \frac{1}{|leaf\_nodes|} \right)$$
   分数越低越好（结构违例少、深度大以支持精准定位、叶节点多以细化证明义务）。采用 $n=3$ 生成候选并选最低分者。
7. **形式模型合成**：每个叶节点 $n_l$ 翻译为状态转移事件 $(n_l.grd, n_l.act)$，与环境模型 $\Gamma$ 组成完整模型 $M$。
8. **失败定位与子树级修复**：
   - 在事件级生成证明义务（守卫良定义性、不变式保持、变体递减），由自动证明器与 SMT 求解器求解；
   - 将失败事件映射回叶节点，识别"所有后代叶节点均因同一不变式/变体失败"的子树，视为共享结构原因（如内部节点引入的共享守卫）；
   - 提示 LLM 在**子树级别**整体修复（修复组 $R$），而非孤立修复单个事件。
9. 重复结构检查与子树修复，直至草图结构有效且派生模型能释放所有证明义务，最终确定性地翻译为状态转移事件集合。

### 2.3 关键概念

- **修复组** $R \subseteq E$：验证失败可能共享同一结构原因的事件集合。理想策略应找到既足够小（避免不必要改动）又足够完整（覆盖同因故障事件）的修复组，避免 $|R|=1$ 的孤立修复或 $R=E$ 的整体重写。

- **实验设计公平**：统一规约语言、统一 LLM、统一工具链，并对基线做适配以保留其能力；指标兼顾语法、证明与运行时语义；消融实验针对性强。
- **工程落地**：集成到 Rodin IDE，展示实用性。

## 8. 不足与局限

- **算力信息缺失**：未报告 GPU 型号、数量、训练/推理时长等，无法评估资源开销与可复现性。
- **构造效度**：以"证明释放"作为模型可验证性的代理，受底层证明器能力限制；无法释放的证明义务未必意味着模型错误，可能只是缺少领域引理、证明提示或需交互式推理。ProGS 是"减少"而非"消除"专家介入。
- **内部效度**：LLM 非确定性使不同运行产生不同草图与修复决策，影响模型质量与迭代次数；性能可能依赖提示设计、解码参数与所选 LLM。论文未报告重复实验的方差。
- **外部效度**：基准仅 27 个系统，且提供了部分环境信息（常量与变量的名称、类型），虽统一应用于所有方法，但限制了 LLM 生成空间的泛化性验证。
- **运行时指标采样不足**：每系统仅 3 条轨迹，部分状态转移事件（如异常处理情形）未被覆盖，导致 ProGS 的 Runtime 覆盖率被低估，也说明运行时语义评估不够充分。
- **RF 略低于 Event-B Agent**：因环境模型固定，无法添加辅助引理，部分 PO 无法释放；同时说明"保持环境模型固定"的设计在提升结构一致性的同时也带来灵活性代价。
- **应用限制**：方法针对状态基形式模型（Event-B 风格），对无证明分解机制的形式语言（如主要用于模型检查的 TLA+、PAT）适配性有限；依赖自动证明器与 SMT 求解器的能力。
- **未来工作方向**：扩展更多边级与子树级形式检查，研究证明草图与形式模型精化、轨迹验证的关系。
