## 摘要
我们提出了一个验证奖励模型（Verification Reward Model, VRM）框架，用于训练语言模型创建和修复芯片验证工件。其核心对象是一个带版本的验证契约，将需求、允许的激励、观测边界、参考行为、评估预算和验收标准绑定在一起。编译器、仿真器、形式化、变异、覆盖率和专家评审证据被转换为可审计记录。确定性的验收检查仍保留在学习模型之外。一个学习得到的结果模型根据规范、生成的工件以及显式遮蔽的部分证据，预测代价高昂的未来证据；一个语义评论器识别有证据支持的弱点；一个确定性的奖励合成器将得到的质量向量转换为任务条件化的训练奖励。扩展包括成对的无故障/故障干预、边际故障发现奖励、不确定性感知的评估调度，以及隔离的跨域学习循环。评估强调经独立验证的故障检测、误报、跨设计族的泛化能力，以及达到指定质量水平的总成本。我们描述了在小型、兼容开源工具的基准上使用轻量级模型进行的首个实验，其中完整的 UVM 能力通过针对特定功能的资格认定被纳入。这是一篇立场论文：我们规定了该框架以及可用于检验它的实验，并且不报告任何训练、EDA 或硅片结果。

## Abstract
We propose a Verification Reward Model (VRM) framework for training language models to create and repair chip verification artifacts. The central object is a versioned verification contract that binds requirements, permissible stimulus, observation boundaries, reference behavior, evaluation budgets, and acceptance criteria. Compiler, simulator, formal, mutation, coverage, and expert-review evidence are converted into auditable records. Deterministic acceptance checks remain outside the learned model. A learned outcome model predicts expensive future evidence from the specification, the generated artifact, and explicitly masked partial evidence; a semantic critic identifies evidence-supported weaknesses; a deterministic reward composer translates the resulting quality vector into task-conditioned training rewards. Extensions include paired clean/fault interventions, marginal fault-discovery rewards, uncertainty-aware evaluation scheduling, and a quarantined cross-domain learning loop. Evaluation emphasizes independently validated fault detection, false alarms, generalization across design families, and total cost to reach a specified quality level. We describe a first experiment on a small, open-tool-compatible benchmark with lightweight models, with full UVM capability admitted through feature-specific qualification. This is a position paper: we specify the framework and the experiments that would test it, and we report no training, EDA, or silicon results.

## 1. 核心问题与整体含义（研究动机与背景）

- **背景**：语言模型已能生成语法上合理的 SystemVerilog、断言与测试平台组件，但将其转化为可靠的验证助手，需要奖励信号真正对齐验证工程师所看重的目标——检测真实设计缺陷、对正确设计不误报、需求可追溯、评估成本有界。
- **核心问题**：简单代理指标无法提供该信号，且极易被策略利用（reward hacking）：
  - 代码覆盖率可上升而检查强度下降；
  - 零失败的断言可能从未被激活（non-vacuous activation 问题）；
  - 无条件打印 error 的 testbench 会"检测"所有故障，同时也在干净设计上失败。
- **关键差异**：与对话式偏好学习不同，该场景存在**可执行的真值**（编译器、仿真器、形式化引擎、变异 campaign），但这些测量**昂贵、部分、易被破坏**。
- **设计问题的本质**：不仅是"奖励什么"，还包括"**哪些量可以学习、哪些必须保持确定性、如何在完整 campaign 完成前使用部分证据**"。
- **整体含义**：论文主张把验证质量视为**契约相关、证据支撑**的量，学习组件只负责预测、诊断与调度，**不得覆盖任何实测结果或验收判定**。

## 2. 方法论：核心思想与关键技术细节

### 2.1 核心思想：三层分离

**可信证据（deterministic）→ 学习预测（learned）→ 预算分配（scheduler）**，三者权限、训练目标与验证集彼此区分。

### 2.2 验证契约（Verification Contract）

任务契约定义为 `C = (S, D, I, O, A, G, B, V)`：

- `S` 需求集合、`D` DUT 版本、`I` 合法输入空间、`O` 可观测性定义；
- `A` 环境假设、`G` 可信 oracle 与目标、`B` 评估预算、`V` 版本与溯源；
- 接口时序、复位语义、支持参数值、允许的非确定性、未完成事务规则均属契约内容。
- **策略只能编辑声明过的工件路径**；不能改动 DUT、参考模型、评分脚本、必需覆盖 bin、变异种群、通过标准或工具约束。契约变更即产生新任务版本。

### 2.3 五个服务（Fig. 1 架构）

| 服务 | 符号 | 职责 | 权限边界 |
|---|---|---|---|
| 可信评估器 | `T` | 执行版本化工具，产出证据 `e = T(C, y)`；掌管退出码、时限、trace、受保护参考文件 | 确定性 |
| 结果模型 | `Oθ` | 在命名评估协议下预测未来测量：`pθ(q>k \| C, y, e≤k, mk)`，掩码 `mk` 标识实际已观测内容；标量效用头 `uθ` 用于排序与调度 | 学习型，不可覆盖实测 |
| 语义评论器 | `Jφ` | 输出需求对齐、工件架构、潜在缺口的结构化评估；每条断言须链接到需求/代码位置/证据记录，未验证诊断标记为**假设** | 学习型，仅用于诊断 |
| 奖励合成器 | `U` | 应用固定有效性规则与版本化标量化，将实测结果转为奖励；可暴露独立预测效用供调度 | **确定性** |
| 评估调度器 | `Aψ` | 选择下一个候选/测试子集/保真度以获取证据；**无权更改验收标准** | 学习型 |

### 2.4 证据表示与信任边界

- **证据记录字段**：契约摘要、候选摘要、工具链摘要、评估阶段、观测时间戳、workload/seed 标识、测量单位、状态、不确定性、原始工件引用；**append-only**。
- **候选可控文本（含注释、日志中的指令）一律视为数据**，防止注入 judge。
- **五种状态**：`pass` / `fail` / `unknown` / `not_run` / `infrastructure_error`。形式化超时通常为 `unknown`，worker 崩溃为 `infrastructure_error`，可复现的候选引发死锁在契约定义完成上界时算任务失败。
- **结构化证据通道**：编译（错误、支持特性、elaboration、顶层绑定）、仿真（完成原因、驱动/观测事务、checker 激活、mismatch、丢弃响应、复位片段、seed）、覆盖率（原始分子/分母/排除项/层级/模型版本）、断言（尝试次数、非空激活、失败、复位禁用区间、未决义务）、变异（有效性状态、故障族、检测机制、reproducer）、运行时（排队/编译/仿真/解析/推理分离）。
- **关键洞察**：零失败断言可能未激活、零 mismatch 的 scoreboard 可能比较了零事务、覆盖率百分比可因分母被削弱而上升——这些必须对评估器可见。
- **证据阶段 E0–

E0–E4（如 elaboration → 编译 → 仿真 → 覆盖率/断言 → 变异），阶段越靠后越贵，且**高阶段失败不应覆盖低阶段证据**；`unknown` 与 `not_run` 必须与 `fail` 严格区分，否则调度器会把"未测"误判为"已通过"。

### 2.5 奖励合成规则（确定性层）

- **固定有效性门槛**：编译通过、DUT 未改动、无契约违规、必需覆盖 bin 全部命中，才允许把 `pass` 计为正奖励；否则为负或中性。
- **非空激活门**：断言/covergroup 只有被实际激活（attempts > 0 且非 vacuous）才计入检测能力；未激活记为待办义务而非通过。
- **分项标量化**：奖励分解为**功能正确性、缺陷检测（变异杀伤）、覆盖达成、契约合规、成本**若干项，权重与阈值版本化，不随训练在线漂移，防止策略通过改变奖励定义获利。
- **成本项显式化**：仿真周期数、编译/形式化时限、CPU 时间进入奖励，避免策略用无限算力换取边际收益。
- **未完成证据处理**：campaign 未跑完时，实测项用已知结果，未知项由 `uθ` 给出**预测效用**用于排序，但**不得**替代实测进入最终奖励；不确定性高时奖励保守（悲观下界），防止乐观偏差被利用。

### 2.6 学习组件与训练目标

- **结果模型 `Oθ`**：预测"若继续跑到阶段 k' 会观测到什么"，输出分布而非点估计；用掩码训练，使模型学会在部分观测下推断；评估时按校准误差、选择性预测覆盖率检验。
- **语义评论器 `Jφ`**：生成结构化诊断（需求-工件-证据三元链接），输出供**人类复核**与**调度先验**使用，不直接产生奖励；提示注入防护要求所有候选生成文本按数据隔离。
- **评估调度器 `Aψ`**：以"每单位算力获得的证据价值"为目标做 bandit/主动学习式选择，可在候选、测试子集、保真度（仿真 vs 形式化）间调度；**验收判定权仍归确定性层**。
- **训练信号来源**：优先使用可执行真值（编译/仿真/变异）产生的稠密分项奖励；偏好/评论模型仅作辅助或诊断，避免把主观偏好引入验收。

### 2.7 防 reward hacking 机制（论文核心主张）

1. **权限分离**：学习组件不得写入证据记录或修改通过标准；
2. **证据 append-only**：历史不可被策略回改；
3. **反事实对照**：变异 campaign 与干净设计并行评估，惩罚"全报错"式伪检测；
4. **分母保护**：覆盖率排除项、必需 bin 与模型版本受保护，禁止通过缩小分母提分；
5. **激活审计**：对断言/scoreboard 强制非空性检查；
6. **预算硬约束**：超时、崩溃与未跑项单独计费，不允许"不跑即通过"。

## 3. 实验设计与评估协议（论文提出的验证方案，非已得结果）

- **任务族**：以带变异注入的 RTL 设计为基准，覆盖组合/时序、握手协议、复位与流水线等故障族；每个任务版本附带契约、参考模型、必需覆盖 bin 与变异种群。
- **对比基线**：代码覆盖率奖励、断言通过率奖励、无门控的 LLM-as-judge 奖励、简单偏好模型奖励。
- **主要指标**：变异杀伤率（真阳性）、干净设计误报率（假阳性）、需求追溯完整率、非空激活率、单位算力缺陷检出数、以及"训练后是否出现奖励与实测脱钩"的监控指标。
- **消融**：去掉语义评论器、去掉调度器、去掉非空激活门、允许学习组件覆盖实测，分别观察 reward hacking 程度。
- **可复现性**：契约、工具链、变异种群与评分脚本版本化，证据记录可回放。

## 4. 贡献与定位

1. 提出**三层权限分离**的验证奖励框架（确定性证据 / 学习预测 / 预算调度）；

4. 系统列举**验证场景特有的 reward hacking 路径**及其确定性防御。

## 5. 局限性与开放问题

- **无实证**：论文为立场性框架，训练、EDA 与硅片结果均未报告，有效性待验证。
- **确定性层设计成本**：契约与证据通道的工程开销大，跨工具链标准化困难。
- **部分证据推断**：结果模型在长尾阶段的外推校准缺乏保证，悲观下界可能拖慢学习。
- **语义评论器的可靠性**：需求对齐诊断本身可能出错，需人类在环，难以规模化。
- **对抗面**：策略可能学习规避激活审计、构造边缘覆盖 bin 或利用调度器偏差，需持续红队测试。
- **成本-质量权衡**：形式化与仿真保真度的最优调度策略仍开放。

## 6. 结论

论文主张：芯片验证中的强化学习奖励不应来自单一代理指标，而应建立在**可执行、版本化、契约绑定**的证据之上；学习组件只承担预测、诊断与调度，验收与奖励合成保持确定性。其价值在于提供一套可审计、抗 hack 的接口规范，而非报告性能提升——是否有效仍需实证研究检验。
