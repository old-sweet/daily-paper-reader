## 摘要
设计验证仍然是硬件开发中资源消耗最大的阶段之一，通常占总体设计工作量的高达70%。尽管近期研究探索使用大型语言模型（LLMs）来自动化测试平台生成，但现有方法大多仅狭隘关注功能正确性，而忽视了覆盖率质量这一关键方面。为弥合这一差距，我们提出 CovR，一个用于自动化测试平台生成的智能体框架，它将自反思循环与基于仿真的反馈相结合，以最大化覆盖率。利用该流程，我们使用强大的教师模型构建了包含16,514个自然规范-RTL-推理-测试平台元组的大规模数据集，从而实现覆盖率感知的监督。在此基础上，我们提出一个专为覆盖率驱动测试平台生成定制的强化学习（RL）框架，利用来自仿真和覆盖率反馈的工具衍生奖励来优化学生模型。实验结果表明，经 CovR 微调的模型在 VerilogEval 和 RTLLM V2.0 上达到93.81% cov@10，在 CVDP 上达到87.76% cov@10，分别比当前最先进方法高出7.97%和3.59%。此外，将微调后的模型重新部署到智能体细化流程中，可进一步将 VerilogEval 和 RTLLM V2.0 上的 cov@10 提升至94.27%，并将 CVDP 上的 cov@10 提升至91.39%。而且，当作为插件式激励引擎集成到完整验证工作流中时，CovR 将覆盖率提升18.95%，将变异检测得分提升1.19%，同时揭示4.46%的未检测失败，凸显了在基于LLM的硬件验证中针对覆盖率进行优化的重要性。

## Abstract
Design verification remains one of the most resource-intensive stages of hardware development, often consuming up to 70% of the total design effort. While recent work has explored using Large Language Models (LLMs) to automate testbench generation, most existing approaches focus narrowly on functional correctness, overlooking the critical aspect of coverage quality. To bridge this gap, we present CovR, an agentic framework for automated testbench generation that combines self-reflection loops with simulation-based feedback to maximize coverage. Using this pipeline, we construct a large-scale dataset of 16,514 natural specification RTL reasoning testbench tuples with a strong teacher model, enabling coverage-aware supervision. Building on this, we propose a reinforcement learning (RL) framework tailored for coverage-driven testbench generation, leveraging tool-derived rewards from simulation and coverage feedback to optimize a student model. Experimental results show that the CovR finetuned model achieves 93.81% cov@10 on VerilogEval and RTLLM V2.0, and 87.76% cov@10 on CVDP, outperforming state-of-the-art approaches by 7.97% and 3.59%, respectively. Furthermore, deploying the finetuned model back into the agentic refinement pipeline further improves cov@10 to 94.27% on VerilogEval and RTLLM V2.0 and 91.39% on CVDP. Moreover, when integrated as a plug-in stimulus engine for full verification workflows, CovR improves coverage by 18.95% and mutation detection score by 1.19%, while revealing 4.46% undetected failures, highlighting the importance of optimizing for coverage in LLM-based hardware verification.

## 2. 方法论

### 2.1 核心思想
CovR 由三部分组成：**(a) 智能体自反思工作流**（用于生成高质量合成数据与推理轨迹）、**(b) 大规模合成数据集**、**(c) 两阶段训练框架**（SFT + GRPO 强化学习），最终得到一个可作为「插件式激励引擎」部署到完整验证流程中的生成模型。

### 2.2 关键技术细节：CovR 自反思工作流（图 2a）
- **输入**：自然语言规范 $N$ + RTL 设计 $V$。
- **流程起点**：先做 **Test Plan Generation**（生成覆盖角落用例、复位场景、多样输入条件的结构化测试策略）；再由 **Testbench Generator** 生成初始激励 $T_{initial}$。
- **两条自反思循环**：
  1. **Testbench 执行循环**：编译/仿真，运行时错误交给 **Reflector**（分析生成器的推理轨迹与工具反馈，产出反思轨迹）→ **Curator**（维护失败、修复、未解决问题的演化上下文）→ **Fixer**（结合最新反馈与历史修复 testbench），直至仿真成功或达到最大迭代次数。
  2. **覆盖率优化循环**：覆盖率报告识别未覆盖分支/条件/状态转移，Generator 针对性补充激励；同样有 Reflector 与 Curator，Curator 还负责发出「不可达状态、无法继续改进」的退出信号；若修复破坏仿真则退回执行循环。
- **选择与标注**：**Testbench Selector** 在可成功执行的候选中选覆盖率最高者作为 $T^*$；**Reasoner** 生成候选推理轨迹，**Verifier** 用结构化评分标准（与 RTL、testbench、覆盖率报告的一致性）选出最优轨迹 $R^*$。最终输出四元组 $(N, V, T^*, R^*)$。
- **工具支持**：兼容开源（Icarus Verilog、Covered）与商用（Synopsys VCS、URG）工具链。

### 2.3 数据集构建（第 3.2 节）
- 用 **gpt-4o-mini** 做自反思循环与推理轨迹验证，用 **DeepSeek-R1** 生成推理轨迹；每个样本 **5 次自反思迭代**，每样本评估 **3 条**候选推理轨迹；仿真与覆盖率反馈用 Synopsys 工具。
- 数据来源：Pyra、VeriThoughts 作为输入，另将 RTLSeek、VeriPrefer、VeriReason、LLM4COV 的 testbench 转为 stimulus-only 形式作为初始种子再精炼。
- 最终产出 **16,514 条**「规范–RTL–推理–testbench」四元组；与 LLM4COV 相比额外包含**显式推理轨迹**。覆盖率分布显示多数样本达高覆盖（line/toggle/condition/branch 中位数 100%，FSM 中位数 75%），低覆盖样本（常数信号、不可达状态等难例）保留在训练集中。

### 2.4 两阶段训练框架（第 3.3 节，图 2b）
- **第一阶段 SFT**：在 $\mathcal{D}=\{(N,V,R^*,T^*)\}$ 上以自回归交叉熵训练，目标序列 $y^*=[R^*,T^*]$（先推理后 testbench）：
  $$L_{SFT}(\theta)=-\mathbb{E}\sum_{t=1}^{|y^*|}\log\pi_\theta(y^*_t\mid N,V,y^*_{<t})$$
  该阶段让模型习得高覆盖率生成模式，但易导致记忆化、泛化受限。
- **第二阶段 RL（GRPO）**：从 SFT 检查点出发，对每个 $(N,V)$ 采样一组候选 testbench $\{T_1,\dots,T_G\}$，并行仿真提取覆盖率，构造**层次化奖励**（式 2）：
  $$R(T_i)=R_{format}w_{fmt}+R_{compile}w_{cmp}+w_{cov}R_{coverage}$$
  权重满足 $w_{cov}>w_{cmp}>w_{fmt}$（实验中 $w_{fmt}=0.02,\ w_{cmp}=0.13,\ w_{cov}=0.85$），保证「格式→编译→覆盖率」的依赖结构：只有格式正确才评估编译，只有成功执行才计算覆盖率。
- **组内归一化优势**（式 3）：$\hat{A}_i=\frac{R(T_i)-\mu_R}{\sigma_R+\delta}$，产生尺度无关的稳定信号。
- **GRPO 目标**（式 4）：在 PPO 式裁剪目标上加入对 SFT 参考策略 $\pi_{ref}$ 的 KL 正则（系数 $\beta$），$r_i(\theta)=\pi_\theta(T_i|N,V)/\pi_{ref}(T_i|N,V)$。

## 6. 主要结论与发现

- **直接推理**：最佳配置 CovR-Qwen2.5-Coder-7B（SFT-W/Reason+RL）达 **88.49% cov@1**（VerilogEval+RTLLM V2.0）与 **73.01% cov@1**（CVDP），分别超教师 GPT-4o-mini **7.22% / 10.91%**，超 LLM4COV **11.85% / 3.97%**。
- **cov@10**：CovR 微调模型达 **93.81%**（VerilogEval+RTLLM V2.0）与 **87.76%**（CVDP），比 SOTA 高 **7.97% / 3.59%**，比 GPT-4o-mini 高 **2.21% / 4.01%**。
- **再入智能体流程**：cov@10 进一步提升至 **94.27%**（VerilogEval+RTLLM V2.0）与 **91.39%**（CVDP）；相对直接推理，平均 cov@1 再提升 **6.68%**。
- **训练收益**：学生模型相比基座模型平均 cov@1 提升 **44.29%**，并平均**超过教师 7.3%**。
- **插件集成**：接入 CorrectBench / PRO-V-R1 后，覆盖率平均提升 **18.95%**，变异检测得分平均提升 **1.19%**，并多暴露 **4.46%** 此前未检测到的失败（Eval1 下降反映的是 FRM/oracle 中的潜在 bug 被激发，而非退步）。
- **总体结论**：在 LLM 硬件验证中**显式优化覆盖率**十分关键——高覆盖率激励不仅能提升覆盖率数字，还能发现功能正确性导向方法漏掉的 RTL 变异体与 FRM/oracle 缺陷。

- **落地导向明确**：作为插件接入两个既有验证框架（CorrectBench、PRO-V-R1），并给出 VCD→JSON 的适配方式，证明工程可集成性；附录案例研究直观展示「多杀变异体」「暴露 oracle bug」的价值。

## 8. 不足与局限

- **算力与成本信息缺失**：仅提及 NVIDIA B200 与 bfloat16，无 GPU 数量、训练时长、仿真调用次数等，复现成本难以评估。
- **依赖商用工具**：数据生成与评测依赖 Synopsys VCS/URG，损害完全可复现性与学术可及性。
- **覆盖类型受限**：只优化**代码覆盖率**（line/toggle/condition/branch/FSM），**功能覆盖率**被列为未来工作，而后者才是验证收敛的核心目标之一。
- **消融不充分**：未逐组件消融 Reflector、Curator、Test Plan、Verifier；未做迭代轮数、$G$、奖励权重、KL 系数 $\beta$ 的敏感性分析；「5 次

次自反思迭代」「3 条候选推理轨迹」等均为固定超参，未讨论其取值对数据质量与最终性能的影响，也未做数据规模缩放（data scaling）分析。

- **缺少统计显著性分析**：主表与消融表中的提升（如 cov@1 提升 6.43%/13.61%）未报告多次随机种子下的方差、置信区间或显著性检验，考虑到 RL 采样本身具有随机性，单次运行的结论稳健性有待验证。
- **奖励设计潜在的 reward hacking 风险未讨论**：覆盖率奖励可能与「有意义的功能行为」脱耦——理论上模型可通过生成大量随机翻转信号刷高 toggle/line 覆盖率，而未必真正逼近角落功能场景。论文虽用层次化奖励缓解「不可执行却拿分」的问题，但未分析「高覆盖率但低功能价值」的退化情形。
- **评测基准规模与代表性有限**：合计约 286 个任务（203 + 83），且以中小规模模块为主，未涉及多模块 SoC、跨时钟域、低功耗状态机等工业级复杂度设计，结论向真实工业验证流程的外推能力尚不明确。
- **基座模型覆盖偏窄**：仅验证 Qwen2.5-Coder-7B 与 Qwen3-4B-Instruct 两个开源模型，未测试更大规模（如 14B/32B）或不同家族（Llama、DeepSeek 等）的模型，也未讨论方法对基座能力的依赖程度与可迁移性。
- **计算与 token 成本不透明**：SFT 与 GRPO 阶段的训练开销、自反思数据生成阶段的 LLM 调用次数与费用、仿真 wall-clock 时间等均未量化，难以与 LLM4COV 等基线做「性价比」层面的对比。
- **教师-学生对比的口径需谨慎解读**：论文强调学生平均「超过教师 7.3%」，但教师（GPT-4o-mini）在评测时未使用与 CovR 相同的智能体自反思流程（仅作 vanilla 对比），该比较可能低估了教师配合同等流程时的上限。
- **功能覆盖率仍是缺口**：论文将功能覆盖率（covergroup/coverpoint）明确列为未来工作，而当前只优化代码覆盖率五维指标，这与工业界以功能覆盖率为验证收敛判据的实践仍存在距离。

## 9. 可复现性与开放性

- **正向**：论文声明**代码已开源**，并给出了完整的数据集构建流程、自反思工作流的角色分工（Reflector/Curator/Fixer/Selector/Reasoner/Verifier）、奖励函数形式与全部超参取值，方法层面的可复现性较好。
- **阻碍**：数据生成与评测链路强依赖 **Synopsys VCS + URG** 商用工具，且未说明是否提供开源工具链（Icarus Verilog + Covered）下的等价复现路径；同时 16,514 条四元组数据的原始生成日志、推理轨迹验证细节、覆盖率报告样例均未在正文中充分展开。
- **建议**：若能公开数据生成脚本、各阶段 checkpoint、以及开源 EDA 工具链下的覆盖率对齐方案，将显著提升社区复现与二次开发价值。

## 10. 对领域的启示与未来方向

- **范式启示**：论文的核心贡献在于把「覆盖率」从一个**事后评价指标**转变为**训练时的优化目标**，并通过工具反馈形成闭环。这一思路可推广到更广的 LLM-for-EDA 任务，如形式化验证断言生成、约束随机激励（constrained random）生成、UVM 序列生成等。
- **方法启示**：**自反思（Reflector + Curator）** 与 **推理轨迹增强的 SFT** 的组合，说明在需要与外部工具反复交互的工程任务中，「显式推理 + 上下文管理」比单纯的多轮反馈更有效，这一结论对软件工程、数据库、编译器测试等 Agentic 场景亦有参考价值。
- **论文自陈的未来工作**：将 CovR 扩展到**功能覆盖率**优化；进一步统一到完整验证流程中（不仅是激励引擎插件）；以及探索更复杂的验证目标（如断言覆盖、跨模块交互覆盖）。

## 11. 总体评价

CovR 是一篇**问题定位清晰、方法论完整、实验落地性强**的工作。它准确抓住了 LLM 硬件验证中「重功能正确、轻覆盖率」的结构性空白，并给出了一个自洽的解决方案：以自反思智能体生产高质量推理增强数据，以两阶段 SFT + GRPO 将覆盖率反馈注入策略，最终以插件形式接入既有验证框架。其**数据集（16,514 条带推理轨迹的四元组）**、**层次化奖励设计**与**插件集成实验**是三项最有价值的贡献；覆盖率提升幅度（cov@1 平均 +44.29%、插件集成 +18.95%）与「多杀变异体、暴露 oracle bug」的案例也具备说服力。

其主要短板集中在**实证充分性的细节**上：组件级消融、超参敏感性、统计显著性、算力成本披露均有缺失，功能覆盖率尚未覆盖，商用工具依赖限制了完全复现。这些属于可补强的工程性缺口，而非方法层面的根本缺陷。

总体而言，该工作为「覆盖率感知的 LLM 硬件验证」提供了一个可复现、可扩展的基线框架，对推动 LLM 在 EDA 验证环节从「能生成」走向「能收敛」具有明确的参考意义。
