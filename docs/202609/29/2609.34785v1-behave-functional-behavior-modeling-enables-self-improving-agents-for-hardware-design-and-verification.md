## 摘要
开发用于硬件设计与验证的智能体需要可靠的正确性反馈。由于硬件规范可能允许具有不同延迟的正确实现，逐周期匹配设计与参考输出可能会拒绝有效设计。为解决此问题，我们提出 BEHAVE，一个通过功能行为建模进行多轮联合硬件设计与验证的智能体框架。我们定义 Behavior IR，以可执行行为模型表达任务功能，而不在规范之外规定实现时序。智能体迭代地开发寄存器传输级（RTL）设计和行为模型，作为该设计的验证参考。我们的评估器 BEHAVE-Sim 使用由随机采样和求解器引导搜索生成的输入激励，将两个产物分别与隐藏的黄金行为模型进行核对。因此，BEHAVE 支持在任务允许的延迟和微架构范围内进行功耗、性能和面积（PPA）探索。在训练过程中，同一评估器无需参考 RTL，即可从规范-行为对中提供可验证的强化学习（RL）奖励。为了实现自我改进，智能体会持续搜索与其能力缺口相关的高层次实现，构建并检查规范-行为对，并在扩展后的任务池上进行训练。我们发布 BEHAVE-Train 和 BEHAVE-Eval，其中包含 600 个经人工审核的规范-行为对，用于真实的硬件工作负载。从 60 个种子任务开始并获取 100 个新任务，自我改进将 Qwen3.8-27B 在 BEHAVE-Eval 上的 RTL pass@1 从 55.0% 提升至 75.0%，达到与使用 540 个任务池进行 RL 相当的性能。

## Abstract
Developing agents for hardware design and verification requires reliable correctness feedback. As a hardware specification may permit correct implementations with different latencies, matching design and reference outputs cycle by cycle can reject valid designs. To address this, we introduce BEHAVE, an agentic framework for multi-turn joint hardware design and verification through functional behavior modeling. We define Behavior IR to express task functionality as executable behavior models without prescribing implementation timing beyond the specification. The agent iteratively develops a register-transfer-level (RTL) design and a behavior model as the design's verification reference. Our evaluator, BEHAVE-Sim, checks both artifacts separately against a hidden golden behavior model using input stimuli generated by random sampling and solver-guided search. BEHAVE thus supports power, performance, and area (PPA) exploration across task-permitted latencies and microarchitectures. During training, the same evaluator provides verifiable reinforcement learning (RL) rewards from specification-behavior pairs without reference RTL. For self-improvement, the agent continually searches for high-level implementations relevant to its capability gaps, constructs and checks specification-behavior pairs, and trains on the expanded task pool. We release BEHAVE-Train and BEHAVE-Eval with 600 human-reviewed specification-behavior pairs for realistic hardware workloads. Starting from 60 seed tasks and acquiring 100 new tasks, self-improvement raises Qwen3.8-27B's RTL pass@1 on BEHAVE-Eval from 55.0% to 75.0%, reaching performance comparable to RL using a 540-task pool.

- **研究背景**：数字芯片开发中，RTL 设计与验证是关键阶段。典型流程是工程师编写 RTL 设计与参考模型（reference model），由 testbench 驱动两者并逐周期比对输出。
- **核心痛点**：硬件规范通常允许具有不同延迟（latency）和微架构的正确实现。若采用**逐周期比对**（cycle-by-cycle comparison），会将符合规范但时序不同的合法设计误判为错误（Figure 1(b)：某设计面积更小，却因延迟不同被拒绝），从而丢失更优的 PPA 权衡方案。

- **整体含义**：论文提出以**功能行为建模**（functional behavior modeling）提供可执行监督——只检查任务定义的功能行为，同时保留规范允许的时序灵活性。这既为推理期提供可靠正确性反馈，也为训练期提供无需参考 RTL 的可验证 RL 奖励，并支撑基于公开高层实现的持续自我改进。

## 2. 方法论

### 2.1 核心思想

- 引入 **Behavior IR**：一种类型化（typed）可执行表示，支持类型化操作、数组、条件、循环和持久状态，用于描述任务功能，而**不规定实现时序**。
- 每个任务配对自然语言规范 **S** 与隐藏的黄金行为模型 **B⋆**；智能体接收 S，独立开发 RTL 设计 **R̂** 与行为模型 **B̂**（作为其设计的验证参考）。
- **任务定义对齐**（task-defined alignment）：RTL 比对时，记录 RTL 接受输入的时钟沿数据，喂给参考行为模型，将其预测输出与 RTL 输出按任务规则匹配，从而允许任务许可的延迟差异；模型–模型比对则直接对同一输入比较输出。

### 2.3 PPA 探索

- 给定 S、固定工作负载 W、频率 f0 与单元库，智能体通过多轮工具交互（BEHAVE-Sim + EDA 反馈）调整并行度等，探索面积–时间权衡。

- **自改进闭环有效**：从 60 个种子任务出发，经 5 轮反馈引导的任务获取扩充至 160 个任务池后继续训练，性能持续优于仅在种子上训练的基线（seed-only），表明 Analyst–Builder–Implementer–Reviewer 流程能够自主发现并补齐能力缺口，且新增任务来自公开高层实现而非人工标注，具备可持续扩展性。
- **任务获取的贡献可分解**（Figure 17）：奖励组构成显示训练后期全通过组（r = 1）比例上升、全失败组（r = 0）比例下降；获取到的任务在难度上与原任务池形成互补，是性能提升的主要来源之一。
- **总体判断**：论文验证了一条"功能行为建模 → 可执行监督 → 可验证 RL → 自我改进"的完整技术路径，核心洞见是**将"任务定义的正确性"与"实现的时序选择"解耦**，从而在不牺牲正确性判据的前提下释放设计空间。

## 7. 局限性与讨论

- **行为模型本身的正确性依赖人工审核**：B⋆ 作为唯一真值来源，其质量直接决定评估可信度。论文通过 921 个任务的人工审核（记录 30 处修订）控制风险，但审核成本随任务规模线性增长，难以完全自动化。
- **Behavior IR 的表达边界**：作为类型化可执行 IR，它天然偏向"可在单次调用内完成的功能行为"，对高度依赖跨周期协议交互、非确定性时序或复杂总线语义的设计，建模与对齐可能存在困难。
- **评估的现实性折中**：BEHAVE-Sim 采用功能级仿真与有界目标分析，不进行门级/时序级验证，也不覆盖功耗、时钟域交叉、复位时序等物理实现问题；PPA 数字来自综合层面的经验前沿，未流片验证。
- **泛化范围有限**：训练实验基于单一 Qwen3.8-27B 模型，自改进的任务获取依赖已有强策略的复盘能力；对更小模型或跨模型家族的可迁移性未做验证。PPA 探索仅覆盖两个量化任务，结论的普适性需谨慎。
- **潜在风险**：若行为模型与规范存在细微偏差，可能系统性地放过错误设计（假阳性）或拒绝合法设计（假阴性）；论文用双向搜索与回放见证缓解前者，但后者（过度严格）在延迟对齐规则下仍需更细致的敏感性分析。

## 8. 结论与整体评价

- **核心贡献**：（1）提出 Behavior IR 与"任务定义对齐"的比对语义，允许规范许可的延迟差异；（2）构建 BEHAVE-Sim 评估器，融合目标引导激励生成、覆盖率/安全目标分类与有界目标分析；（3）发布 600 个经人工审核的规范–行为任务对（BEHAVE-Train 540 + BEHAVE-Eval 60）并扩展三个外部 benchmark；（4）给出可验证 RL 与反馈引导任务获取的自我改进闭环；（5）在 PPA 探索中展示面积–时间权衡的自动发现能力。
- **方法学价值**：论文的深层意义在于提出了一种**"以功能意图为监督、以微架构自由为奖励"的范式**，为硬件智能体提供了既不依赖参考 RTL、又不因时序差异而误判的验证基础设施，这对缓解配对硬件数据稀缺具有普适意义。
- **实证强度**：实验覆盖面广（4 个 benchmark、5 条流水线、多模型、RL 与自改进、PPA 与 HLS 对照），基线适配与补丁公开提升了可复现性，评分统一使用隐藏黄金模型增强了公平性；但消融维度与模型多样性仍有提升空间。
- **总体判断**：BEHAVE 在"如何为硬件设计智能体提供可靠、可扩展且不束缚实现的正确性监督"这一关键问题上给出了完整且可操作的答案，是硬件智能体评测与训练基础设施方向上具有代表性的工作；其局限主要来自行为模型审核成本与功能级验证的固有边界，而非方法框架本身的缺陷。
